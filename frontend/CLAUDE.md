## 🚨 마음대로 정하지 마라 — 막히면 멈추고 물어라

**아래 것들은 막혔다는 이유로 우회하지 마라. 하던 일을 멈추고, 무엇에 막혔는지 보고하라.**

| 절대 임의로 바꾸지 말 것 | 왜 |
|---|---|
| **운영 DB의 스키마·제약·트리거·RLS** | 되돌리기 어렵고, 모든 사용자에게 즉시 영향을 준다 |
| **법적 요건에 걸린 규칙** (만 14세 미만 판별, 생년월일 필수, 보호자 동의, 약관·개인정보) | 코드 편의로 풀 수 있는 것이 아니다 |
| **인증·권한의 범위** (누가 무엇을 할 수 있는가) | 뚫리면 데이터가 새고, 새고 나서야 안다 |
| **가격·용량·보관 정책** | 원가와 약속이 걸려 있다 |
| **PRD에 적힌 기능을 없애거나 뜻을 바꾸는 것** | 기획 결정이지 구현 판단이 아니다 |
| **사용자 데이터 삭제·초기화** | 되돌릴 수 없다 |

**"이걸 안 바꾸면 내 작업을 끝낼 수 없다"는 것은 우회할 이유가 아니라 보고할 이유다.**
그 벽이 바로 사람이 결정해야 할 지점이다. 작업을 절반만 끝내고 "여기서 막혔고,
뚫으려면 X를 바꿔야 하는데 그 판단은 제 몫이 아니다"라고 말하는 편이
**전부 끝내놓고 몰래 바꾼 것보다 훨씬 낫다.**

실제로 있었던 일(2026-08-24): 한 작업자가 카카오 로그인을 붙이다 생년월일 필수 제약에
막히자, 묻지 않고 **운영 DB의 NOT NULL 제약을 풀고 가입 트리거를 다시 썼다.**
판단 자체는 타당했지만 **만 14세 미만 판별이라는 법적 요건이 DB에서 앱 코드로 내려앉았고**,
사용자는 그런 지시를 한 적이 없다. 전부 되돌렸고 카카오는 보류됐다.

## UX 기준선 (2026-08-20 개정)

**"시니어라서"를 근거로 판단하지 마라.** 주 사용자는 2030이고, 동반 사용자인 부모(5060)는
카카오톡을 무리 없이 쓴다. 조심할 대상이던 어르신(70+)은 주 대상이 아니다.

새 기준은 **카카오톡**이다 — 카톡이 이미 가르친 동작(롱프레스·스와이프·아이콘 버튼)은
"배워야 할 것"으로 치지 않는다. 규칙 전문은 `_workspace/12_ux_baseline.md`.

⚠️ 코드 주석 곳곳에 아직 "시니어 사용자라서…"라는 옛 근거가 남아 있다(약 55곳).
**그 문장을 새 판단의 근거로 인용하지 마라.** 손대는 김에 보이면 고치되,
멀쩡한 파일을 그 이유만으로 열지는 않는다.

## 하네스: 프로토타입 구조 이식 → 글로벌 디자인 루틴 (2026-08-25 전환)

**민규ver.html 프로토타입을 그대로 이식하는 방향은 폐기했다.** 이제 목표는 프로토타입
구조를 베끼는 게 아니라 **더 매끄러운 UX/UI**다. `oneuldo-port`로의 자동 라우팅은
중단한다.

**현재 라우팅:** 화면 작업(신규 화면·기존 화면 개선 모두)은 전역 `~/.claude/CLAUDE.md`의
"디자인 관문 — 화면 작업 루틴"을 따른다 — 기준 확인 → `frontend-design-direction`으로
방향 → `superdesign`으로 시안 비교 → `frontend-design`으로 구현 → `make-interfaces-feel-better`로
마감 → 스크린샷 검증 → (화면 3개 이상 누적 시) `design-system` 감사.

`oneuldo-port`, `prototype-extract`, `nextjs-port`, `residue-scan` 스킬은 더 이상
기본 라우팅 대상이 아니다. 파일은 남아있고 필요하면(과거 이식 화면과의 정합성 확인 등)
직접 호출할 수 있지만, 새 작업의 기본 경로는 아니다.
