## 들어오면 안 되는 것이 들어왔다

### 🔴 [막음] 내부 합성 이메일이 화면에 뜰 길이 열려 있다

`src/lib/username.ts:79`에 `isInternalEmail()`이 있고 주석은 이렇게 약속한다 —
"이 주소는 사람에게 절대 보여주지 않는다". 그런데 **부르는 곳이 한 군데도 없다** (grep 결과 0건).

실제 표시 자리인 `src/app/my/page.tsx:61-65`는 방어 없이 그대로 찍는다.

```
) : user.email ? (
  <p className="text-base text-muted">이메일</p>
  <p className="break-all text-lg text-ink">{user.email}</p>
```

지금 안 새는 이유는 코드가 막아서가 아니라 **DB 트리거가 `@id.oneuldo.local`을 null로 넣어주기 때문**이다.
트리거 하나에 전부를 걸어둔 구조다. 트리거가 안 걸린 계정이 한 줄이라도 생기면
사용자는 자기가 적은 적 없는 `authtest02@id.oneuldo.local`을 자기 마이 화면에서 보게 된다.
사용자 지시("이메일 대신 아이디")를 정면으로 깨는 화면이다.

**고칠 것**: `user.email && !isInternalEmail(user.email)` 로 조건 한 겹. 이미 만들어 둔 함수를 쓰기만 하면 된다.

## 화면 문구 검토

### 🟡 [확인 필요] 성공 배지가 초록이 아니다 — 디자인 관문에 올려야 한다

캡처 18은 `✓ 3초 이상 충족 완료`를 **연초록 칩**으로 보여준다. 직접 열어 확인했다.
구현은 가라앉은 면으로 뒀다. 이식가 사유: `globals.css`에 초록 토큰이 없고 "색을 즉흥으로 만들지 않는다"가 우선.

**그 판단은 맞다.** 규칙을 어기고 초록을 지어내는 것보다 낫고, ✕/✓ 기호가 함께 바뀌어 상태는 전달된다.
다만 **캡처가 최종 권한**이므로 이 차이는 남아 있는 것이다.
→ 성공 토큰(`--color-success` / `--color-success-soft`)을 디자인 관문에서 정식으로 추가할지 사용자가 정해야 한다.

### 🟡 [확인 필요] 생년월일 입력칸 모양이 `참고/1.png`과 다르다

참고 이미지는 **한 칸에 "1985년 8월 9일"**이 통으로 보이고, 그 칸을 누르면 휠이 올라온다.
구현은 `[1985] 년 [8] 월 [9] 일` **세 칸 + 옆에 [고르기] 버튼**이다.

이식 기록의 사유: 한 칸짜리로 만들면 그 칸에 키보드로 칠 수가 없다(누를 대상이 하나뿐이라 둘 중 하나를 포기하게 된다).
사용자가 "키보드 입력 시 연도 4자리 제한"을 함께 지시했으니 **키보드 입력은 살려야 하는 요구다.**
두 지시를 모두 만족시키려면 이 구조가 불가피해 보인다.

→ **판단하지 않고 넘긴다.** 사용자가 "참고 이미지 모양 그대로"를 우선하면 입력칸을 한 칸으로 합치고
키보드 입력은 그 칸 안에서 숫자만 받는 방식으로 다시 짜야 한다. 지금은 기능이 아니라 **취향의 갈림길**이다.

### 그 밖의 문구

**폐기 용어 (`관계방`·`구성원`)** — 이번에 손댄 25개 파일 전수 grep:

- **화면에 보이는 문구: 0건** ✓
- 주석·`console.error`에 6건 (`invite/page.tsx:15`, `settings/page.tsx:16,17,44,131`, `my/page.tsx:23`, `withdraw-form.tsx:21,71,179`)
  → 사용자 눈에 닿지 않는다. 급하지 않지만 다음에 그 파일을 열 때 함께 정리하면 좋다.

**`src/app/login/page.tsx:17`** — `"소중한 사람에게 매일 마음 한마디를."`
`마음 한마디`는 03_capture_flow 용어표에서 버린 말이다(→ 추억/게시물).
`git diff` 확인 결과 **이번에 바뀐 줄은 아니다**(바로 아래 안내 문구만 "이메일로 로그인 → 아이디로 로그인"으로 고쳤다).
같은 표현이 사서함·신고·약관 등 손대지 않은 화면 전반에 퍼져 있어 **이 단계에서 여기만 고치면 오히려 어긋난다.**
→ 용어 통일을 하나의 작업으로 따로 잡는 것을 권한다.

**`src/lib/actions/auth.ts:140`** — 시니어 기준 위반 소지:

```
return { error: `가입 중 문제가 생겼어요: ${error.message}` }
```

`error.message`는 Supabase가 주는 **영어 기술 문구**다. 화면에 그대로 뜬다.
이 줄도 `git diff` 결과 **기존 코드**지만, 아이디 가입 경로가 다시 이 길을 지나가고
`compose-form.tsx`는 같은 상황을 이번에 "영어 기술 문구가 시니어 화면에 그대로 뜬다"며 한국어로 감쌌다(53행).
**같은 앱 안에서 기준이 두 개다.** 원문은 `console.error`로만 남기고 화면에는
"가입 중 문제가 생겼어요. 잠시 후 다시 시도해주세요." 로 두는 편이 앞의 판단과 일치한다.

**잘 쓴 문구** — 지적 없다. 캡처 문구는 글자까지 그대로 옮겼고, 새로 쓴 것도 죄책감 없는 톤을 지켰다:
"아이디는 영문 소문자와 숫자만 쓸 수 있어요. (한글·대문자·특수문자 불가)",
"이미 사용 중인 아이디예요. 다른 아이디로 만들어주세요."(사용자에게 '이메일'이라는 말을 한 번도 꺼내지 않는다),
"태어난 해는 1900년부터 2026년 사이로 입력해주세요.", "1985년 2월은 28일까지 있어요."
— 무엇이 잘못됐고 무엇을 하면 되는지가 한 문장에 다 있다.
