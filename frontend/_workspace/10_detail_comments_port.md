새로 만든 것은 사진 페이저·댓글바·댓글 목록·댓글 ⋯ 뿐이다.

## 1. DB 변경 (마이그레이션 2건)

### `memory_comments` (신규 테이블)

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `id` | uuid PK | |
| `memory_id` | uuid NOT NULL | `memories(id)` ON DELETE CASCADE |
| `author_id` | uuid NULL | **`public.users(id)` ON DELETE SET NULL** (아래 판단 참고) |
| `created_at` | timestamptz NOT NULL | |
| `deleted_at` | timestamptz NULL | 소프트 삭제 |
| `body` | text NULL | 텍스트 댓글 |
| `voice_path` | text NULL | voice 버킷 경로 `{room_id}/…` |
| `voice_duration_sec` | int NULL | 3~60 |

CHECK 2개:
- `memory_comments_kind` — `body`와 `voice_path` 중 **정확히 하나**. 음성이면 길이 3~60초
  (`VOICE_MIN_SEC`·`VOICE_MAX_SEC`와 같은 값).
- `memory_comments_body_length` — `char_length(btrim(body))` 1~300 (`TEXT_MAX_LENGTH`와 같은 값).
  공백만 남긴 댓글도 빈 댓글이라 막는다.

RLS (기존 `memory_likes`/`memory_photos` 패턴 그대로):
- select: 그 게시물이 있는 방의 멤버(`is_room_member`) **and** 내가 차단하지 않은 사람의 댓글
- insert: `author_id = auth.uid()` and 그 방의 멤버 and 게시물이 안 지워졌을 것 and `deleted_at is null`
- update: 본인 것만 (소프트 삭제가 이 경로로 일어난다)
- **delete 정책 없음** — 물리 삭제는 길 자체가 없다

인덱스 2개 (`list_migrations`·`pg_indexes`로 기존과 겹치지 않는 것 확인):
- `memory_comments_memory_idx (memory_id, created_at) where deleted_at is null`
  — 목록 조회와 개수 세기가 둘 다 이 모양이다. 부분 인덱스라 지운 댓글은 아예 안 들어온다.
- `memory_comments_author_idx (author_id)` — 탈퇴 때 SET NULL로 이 표를 훑는다
  (`memories`의 `idx_memories_author`와 같은 이유)

### `memory_comments_no_physical_delete`

새 표에 기본 권한으로 딸려온 `DELETE`를 `authenticated`에서 거뒀다.
RLS에 DELETE 정책이 없어 이미 막혀 있었지만(실측: 0행), 권한이 남아 있으면
"지울 수 있는데 정책이 없어서 안 되는 것"처럼 읽힌다. 의도를 스키마에 적어둔다.

### 스토리지 — 새 버킷·새 정책 없음

음성 댓글 파일은 기존 `voice` 버킷을 그대로 쓴다. 기존 정책이
`bucket_id in (media, voice, covers) and is_room_member(path_uuid(name))`이라
경로를 `{room_id}/…`로만 지으면 그대로 커버된다.

## 3. 판단들

### ① 댓글 삭제는 **롱프레스가 아니라 ⋯ 버튼**

프로토타입은 댓글을 길게 눌러 메뉴를 띄웠다. 버튼으로 바꿨다:
- 길게 누르기는 화면에 흔적이 없어 **있는 줄 모르면 영영 못 쓴다.** 주 사용자가 시니어다.
- 키보드·낭독기 사용자에게는 그 동작 자체가 없다.
- 글자를 끌어 복사하려는 손짓과 겹친다.

게시물의 ⋯(`MemoryMenu`)와 같은 기호라 새로 배울 것도 없다.
누르면 [삭제] 한 줄짜리 메뉴 → 확인 창. 게시물 삭제와 같은 걸음 수다(되돌릴 수 없으니까).
**남의 댓글에는 ⋯ 자체를 그리지 않는다** — 회색으로 눌리지 않게 두면 계속 누르게 된다.

### ② `author_id`가 `auth.users`가 아니라 `public.users` ON DELETE SET NULL — **지시와 다르게 했다**

지시는 "`author_id`(auth.users 참조)"였다. 프로젝트 안에 두 갈래가 이미 있다:
- 개인 표시(`memory_likes`·`hides`·`saves`) → `auth.users` CASCADE
- **내용**(`memories.author_id`) → `public.users` SET NULL

댓글은 내용 쪽이다. CASCADE로 묶으면 한 사람이 탈퇴할 때 **남의 방에 남긴 대화가 통째로**
사라지고, voice 버킷의 음성 댓글 파일은 가리키는 행 없이 남는다. SET NULL이면 댓글은 남고
이름만 `roomMemberName`이 '탈퇴한 사용자'로 바꾼다 — 게시물과 똑같은 규칙이다.
(탈퇴 함수 주석도 "내가 남긴 마음은 상대 사서함에 익명으로 남는다"고 적고 있다.)

### ③ 3초 미만 문구는 캡처와 조금 다르다

캡처는 "음성 녹음은 3초 이상이어야 해요"라고 말하며 취소한다.
우리는 `VoiceRecorder`를 그대로 재사용했고, 그 부품은 녹음을 버리고 배지를
**"✕ 3초 이상 녹음해 주세요"**(빨강)로 되돌린다. 뜻은 같고 자리만 다르다.
같은 말을 하려고 녹음기를 한 벌 더 만드는 것보다, 두 화면의 녹음 규칙이 한 곳에 있는 편이 낫다.

### ④ 상세 화면에는 탭바를 두지 않았다

프로토타입 마크업의 마지막 자식이 댓글바다(탭바 없음). 캡처 24·25도 그렇다.
아래 한 자리를 댓글바가 쓴다 — 둘을 겹쳐 쌓으면 입력칸이 화면 절반까지 올라온다.

### ⑤ 없는 게시물은 기본 404 대신 우리말 화면

`notFound()`를 부르면 영어 기본 404가 뜬다. 지워졌거나·남의 방이거나·주소가 틀린 셋을
구분해 알려줄 방법은 없지만, **돌아갈 길은 줘야 한다.** "이 추억은 볼 수 없어요" +
[앨범방으로 돌아가기].

### ⑥ 💬 는 링크, ♡ 는 버튼

같은 줄에 있지만 하는 일이 다르다. 화면이 바뀌는 것은 링크여야 새 탭·뒤로가기가 산다.
피드의 💬 는 예전에 "누를 수 없는 글"이었는데, 이제 갈 곳이 생겨 링크가 됐다.

### ⑦ 사진 페이저는 브라우저 스크롤 + CSS 스냅

넘기는 일은 브라우저가 한다(손가락·트랙패드·키보드 방향키가 전부 공짜로 딸려온다).
자바스크립트는 **몇 번째를 보고 있는지 세는 것만** 한다 — 배지를 그리려고 'use client'다.
한 장뿐이면 배지도 없고 초점도 받지 않는다("1/1"은 더 넘길 수 있다는 뜻으로 읽힌다).

### ⑧ 잔여데이터 — `key={memoryId}`

페이저와 댓글바에 `key`를 붙였다. 다른 게시물 상세로 옮기면 두 부품이 통째로 새로 만들어져
**쓰다 만 글·보고 있던 사진 자리**가 따라오지 않는다. 브라우저로 실제 확인했다(아래 §5).

### ⑨ `residue-scan` 면제 1건 — `dom-state-machine`

`comment-bar.tsx`가 `document.getElementById(COMMENT_END_ID)`로 목록 끝을 찾아 굴러간다.
그 자리를 그리는 쪽은 서버 컴포넌트라 ref로 잡을 수 없다. **DOM에 무엇을 쓰지도, 화면을
감추거나 되살리지도 않는다** — 프로토타입의 화면 전환 방식과 다르다. 파일 안에 이유와 함께 적었다.

## 4. 고친 버그 (내가 만들고 브라우저에서 잡은 것)

**이모지 팝오버가 한 줄로 무너졌다.** `grid-cols-6`인데 실제 폭이 46.75px(한 칸)이었다.

그 부모가 아이콘 버튼 하나 크기라 6칸이 거기에 맞춰 접힌 것이다. `w-max`를 줘서 고쳤다
(실측 325px, 6×2 격자). 스크린샷으로 확인.

## 5. 브라우저 실확인 (실제 Supabase, 로그인 상태, "우리 가족 행복방")

| 확인한 것 | 결과 |
|---|---|
| 피드 사진 누르기 → 상세 진입 | 됨 (`/memories/{id}`) |
| 피드 💬 누르기 → 상세 진입 | 됨 |

| 음성 댓글 — 4초 | 올라가고 댓글 3, 시트 닫힘, 목록에 재생바(0:04) |
| 댓글 삭제 (⋯ → 삭제 → 확인) | 댓글 2로 줄고 화면에서 사라짐 |
| 남의 댓글 | ⋯ 안 뜸 (다른 사용자 댓글을 넣어 확인) |
| 피드로 돌아가 댓글 수 | "댓글 3개 보기" — 소프트 삭제된 것 빠짐 |
| 다른 게시물 상세로 이동 | 댓글 0, 입력칸 빈 채 — 앞 게시물 잔여 없음 |
| 콘솔 | error·warn 0건 |

### DB로 확인한 것 (실제 로그인 사용자 역할로)

- 소프트 삭제: 지운 댓글의 행이 그대로 있고 `deleted_at`만 찼다
- 남의 댓글 지우기 시도 → 0행 (RLS `memory_comments_update`)
- 물리 삭제 시도(내 댓글) → 0행 (DELETE 정책 없음)
- CHECK: 빈 댓글 / 글+음성 둘 다 / 2초 / 61초 / 공백만 / 301자 — **전부 막힘**
- `get_advisors` 보안·성능 — 이번 표 때문에 새로 생긴 경고 없음
  (성능의 "unused index"는 방금 만든 인덱스라 당연한 것)

### 확인에 쓴 임시 데이터는 지웠다

남의 댓글 확인용으로 넣은 댓글 1줄과 사진 1장짜리 테스트 게시물은 SQL로 직접 넣은
가짜라서 다시 지웠다. 화면에서 실제로 남긴 댓글 2개(텍스트·음성)와 지운 댓글 1개는 남아 있다.

## 7. 다음 단계에 넘길 것

- 댓글 **수정**은 없다. 캡처에도 없고, 짧은 한마디를 고치는 것보다 지우고 다시 쓰는 편이 빠르다.
- 댓글 **알림**은 5단계(알림 모달)의 몫이다. 지금은 남겨도 아무에게도 알려지지 않는다.
- 댓글이 아주 많아지면 나눠 읽기(페이지)가 필요하다. 지금은 한 게시물의 댓글을 전부 읽는다 —
  방 하나에 게시물이 손에 꼽을 때라 아직 이르다.
- 음성 댓글에도 게시물처럼 **파형 실측값**을 넘기면 좋겠지만(지금은 재생을 눌러야 파형이 뜬다),
  그건 `VoicePlayer`의 기존 규칙 그대로다. 바꾸려면 피드까지 함께 봐야 한다.
