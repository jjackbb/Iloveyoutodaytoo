## 2. 판단이 갈렸던 지점

### 2-1. 크롭 부품 — 공용화하지 않고 **따로 만들었다**

`src/app/rooms/new/cover-crop-dialog.tsx`(2:1 커버용)를 읽고 **조작 방식은 그대로**,
비율·출력·강조 모양만 바꿔 새 파일로 만들었다. 공용 훅으로 뽑지 않은 이유:

- 지금 쓰는 곳이 두 곳뿐이다. 공용화하면 "비율·출력크기·덧그림·안내문구·제목"을 전부
  옵션으로 받는 부품이 되는데, 그건 지금 필요한 것보다 큰 물건이다.
- 커버는 2:1이라 세로를 `w / ASPECT`로 계속 나눠 쓰지만, 프로필은 정사각형이라
  `size` 하나면 끝난다. 억지로 합치면 양쪽 다 읽기 어려워진다.

**대가:** 조작 방식(핀치·휠·손잡이·키보드)을 고칠 때는 두 파일을 같이 봐야 한다.
두 파일 주석에 서로를 가리키는 문장을 남겼다. 세 번째 화면이 생기면 그때 뽑는다.

바뀐 것:
| | 커버 | 프로필 |
|---|---|---|
| 비율 | 2:1 | 1:1 |
| 출력 | 1200×600 JPEG | **512×512 JPEG** |
| 틀 강조 | 밝은 네모 + 삼분할선 | **원**(어두운 덮개가 동그랗게 뚫린다) + 삼분할선, 네모는 점선으로 흐리게 |
| 안내 문구 | "밝은 틀 안이 커버가 돼요" | "동그란 안쪽이 프로필 사진이 돼요" |

**동그란 PNG로 굽지 않는다.** 동그랗게 보이는 것은 화면(CSS `rounded-full`)의 일이다.
투명 PNG는 같은 화질에서 파일이 몇 배 크고, 나중에 사각형으로 쓰고 싶어지면 되돌릴 수 없다.

### 2-2. 이메일/아이디 표시 분기

캡처는 `minkyu***@gmail.com`처럼 이메일을 가려서 보여준다. 우리는 아이디 로그인 체계라
그대로 옮길 수 없다.

```
username 이 있으면          → 아이디를 **가리지 않고** 그대로
(내부 주소에서 꺼낸 아이디도 같음)
진짜 이메일로 가입한 계정만  → maskEmail()로 앞부분 절반(최대 6자)만 남기고 ***
합성 주소(@id.oneuldo.local) → 한 글자도 안 보여준다
```

아이디를 가리지 않는 이유: 내 화면에서 내 아이디를 못 읽게 하면 잊어버렸을 때 확인할 곳이
없어진다. 가려야 할 것은 남에게 보이는 개인정보이지 본인이 봐야 할 로그인 이름이 아니다.
(사용자가 최근에 정한 원칙. `src/app/my/page.tsx` 옛 주석에도 같은 판단이 있었다.)

**캡처와 다르게 한 것:** 캡처는 라벨 없이 값만 있지만, 우리는 `아이디 porttest01`처럼
앞에 한 단어를 붙였다. 값만 두면 아이디가 또 하나의 이름처럼 읽힌다.

### 2-3. 옛 프로필 사진은 **지운다**

새 사진을 올릴 때마다 새 이름(`{user_id}/avatar-{시각}.jpg`)으로 올리고, DB 갱신이
성공한 뒤에 옛 파일을 지운다.

- 물리 삭제 금지 원칙과 어긋나지 않는다. 그 원칙이 지키려는 것은 **상대에게 남아야 할
  기록**(사서함·추억)이다. 옛 프로필 사진은 아무 행도 가리키지 않는 파일이라
  남겨두면 누구도 볼 수 없는 채로 용량만 차지한다.
- 같은 이름에 `upsert`로 덮어쓰지 않는 이유: 주소가 그대로면 브라우저·CDN이 옛 사진을
  계속 보여준다.
- 순서: 올리기 → DB 갱신 → 옛 파일 삭제. DB 갱신이 실패하면 방금 올린 파일을 도로 지운다.

**탈퇴 시 정리 목록에 avatars는 없었다.** `withdraw.ts`의 `FILE_BUCKETS`는
`voice/media/covers` 셋뿐이고, 셋 다 경로가 `{room_id}/…`라 그 반복문에 avatars를
끼워 넣을 수 없다(경로가 `{user_id}/…`). 그래서 `removeMyAvatarFiles()`를 따로 만들어
탈퇴 흐름에 넣었다. 처리방침 제8조 2항("복구 불가능한 방법으로 영구 삭제")이 이 파일에도
적용된다.

### 2-4. 사진 지우기(×)에 확인 단계를 두었다

캡처의 작은 ×는 사진을 지우고 기본 그림으로 되돌리는 버튼으로 판단했다. 다만 곧바로
지우지 않고 `?remove=1`로 확인 한 걸음을 둔다 — `/my/blocks`의 차단 해제와 같은 방식이다.

- 되돌릴 수 없는 동작이다(원본 파일이 지워진다).
- 작은 ×는 손이 미끄러지기 쉬운 자리다. 시니어 사용자가 주 대상이다.
- 브라우저 자바스크립트 없이도 동작한다(평범한 `<form>` + 링크).

**사진이 없으면 × 자체를 그리지 않는다.** 눌러도 아무 일이 없는 버튼은 고장 난 화면으로
보인다. 캡처는 기본 그림 위에도 ×가 있지만 그건 따르지 않았다.

### 2-5. 비밀번호 — 기존 비밀번호로 **다시 로그인해서** 확인한다

`supabase.auth.updateUser({ password })`만 쓰면 기존 비밀번호를 묻지 않고 바뀐다.
로그인한 기기를 잠깐 두고 자리를 비운 사이 남이 갈아치울 수 있다는 뜻이다.
서버가 기존 비밀번호를 검증할 방법은 `signInWithPassword`로 실제로 로그인해 보는 것뿐이다.

```
1) 세 칸 검사(빈칸·불일치·8자·기존과 같음)
2) signInWithPassword(로그인주소, 기존비밀번호)   ← 여기서 틀리면 끝
3) updateUser({ password: 새비밀번호 })
```

로그인 주소는 `auth.getUser().email`을 먼저 쓰고, 비어 있으면 `usernameToEmail(username)`
으로 합성한다(가입 때와 같은 규칙, `lib/username.ts`).

**제출 버튼 잠금:** 사용자 지시대로 세 칸이 다 차고 새 비밀번호와 확인이 같아야만 열린다.
프로젝트 기본 원칙(탈퇴 화면)은 "잠그지 말고 눌러보게 하라"이지만, 지시가 우선이다.
대신 **왜 안 눌리는지를 버튼 위에 글로 적었다** — 잠긴 버튼만 있고 이유가 없으면
시니어 사용자에게는 고장 난 화면이 된다.

**다이얼로그를 열 때마다 `key`를 바꿔 통째로 새로 만든다.** `useActionState`는 담긴 결과를
스스로 비우지 못해서, 그대로 두면 다시 열었을 때 지난번 "바꿨어요"가 그대로 떠 있다.
폐기된 프로토타입의 잔여데이터와 같은 종류라 애초에 남지 않게 했다.

### 2-6. 잔여 판단(작게)

- **`/my` 아래쪽 "회원 탈퇴" 링크는 그대로 뒀다.** 내 정보에도 "계정 탈퇴"가 생겨 두 곳이
  됐지만, 개인정보보호법상 탈퇴는 찾기 쉬워야 한다. 입구가 둘인 것이 하나보다 낫다.
- **닉네임(이름)은 여기서 바꾸지 않는다.** 캡처에 바꾸는 자리가 없고, 이름은 방마다 상대가
  나를 알아보는 표시다. 방별 별명은 별도 작업으로 예정돼 있다.
- **`next/image`를 쓰지 않았다.** 서명 주소가 한 시간마다 바뀌어 최적화 캐시가 맞지 않고,
  512px JPEG 한 장(40KB 안팎)이라 최적화로 얻을 것이 거의 없다.
- **"함께한 지 N일째"는 가입 당일이 1일째**다. 0일째라고 적히면 아직 시작도 안 한 것처럼
  읽힌다. KST 자정 기준(`kstDaysBetween`)이라 서버·기기 시간대가 달라도 숫자가 안 흔들린다.
- 화면 폭 390~414px에서 "오늘도 사랑해와 함께한 지 N일째"가 **두 줄로 접힌다**(17px 기준).
  글자를 줄이는 대신 접히게 두었다 — 시니어 기준 17px를 깎지 않는다.

## 5. ⚠️ 곁다리로 찾은 버그 — **회원 탈퇴가 통째로 안 되고 있었다**

`src/lib/actions/withdraw.ts`

```ts
// 고치기 전 — 500 오류
const callWithdrawAccount = supabase.rpc as unknown as WithdrawAccountRpc
```

supabase-js의 `rpc`는 프로토타입 메서드이고 그 안에서 `this.rest`를 쓴다. 함수만 떼어
변수에 담으면 `this`가 사라져 호출하는 순간
`TypeError: Cannot read properties of undefined (reading 'rest')`로 터진다.

실제 증상(재현 2회):

- `/my/withdraw`에서 "탈퇴하기" → **HTTP 500**, "A server error occurred."
- 그런데 **파일 정리는 이미 끝난 뒤**라 프로필 사진만 사라지고 계정은 그대로 남았다.
  (같은 이유로 방 파일도 지워졌을 것이다.)
- DB 함수 `withdraw_account` 자체는 멀쩡하다 — supabase-js로 직접 부르면 성공한다.

고침:

```ts
const callWithdrawAccount = supabase.rpc.bind(supabase) as unknown as WithdrawAccountRpc
```

고친 뒤 UI로 탈퇴 → "탈퇴가 끝났습니다" + `auth.users`/`public.users`/avatars 전부 0건.

**이건 내 이번 작업으로 생긴 버그가 아니다.** `types/database.ts`에 함수가 없어 캐스팅으로
우회하면서 들어간 것으로 보인다. `types/database.ts`를 다시 생성해 `withdraw_account`가
들어오면 이 캐스팅과 `.bind`를 통째로 지울 수 있다.
