# 프로토타입 추출

## 왜 스크립트로 하는가

`PRD/references/prototype-mingyu.html`은 6,957줄이다. 구성은:

| 줄 | 내용 | 이식 대상 |
|---|---|---|
| 1~1,991 | `<style>` — CSS 전부 | **그렇다** (색·글자크기 제외) |
| 1,991~2,933 | 마크업 — 화면 19개 | **그렇다** |
| 2,933~6,957 | `<script>` — 상태 기계 | **아니다. 이게 폐기 원인이다** |

매번 통째로 읽으면 컨텍스트가 다 찬다. 손으로 자르면 CSS 규칙을 빠뜨린다.
그래서 자르기는 스크립트가 한다.

## 사용법

```bash
# 화면 목록
node .claude/skills/prototype-extract/scripts/extract-screen.mjs --list

# 화면 하나 뽑기 (6~18KB로 줄어든다)
node .claude/skills/prototype-extract/scripts/extract-screen.mjs home --out _workspace/home_raw.md
```

스크립트가 하는 일: 화면 섹션 + 그 화면이 쓰는 CSS 규칙만 + (body가 비었으면) JS 렌더 함수.

## 반드시 알아야 할 함정

### body가 비어 있는 화면이 있다

`home`·`album`·`detail`은 마크업의 `<div class="body">`가 **비어 있다.** JS가 채운다.
마크업만 보고 이식하면 **껍데기만 있는 빈 화면**이 나온다.

스크립트가 이 경우를 감지해 렌더 함수를 함께 뽑고, 명세 머리말에 표시한다.
그 함수에서 읽어낼 것은 **HTML 모양**뿐이다. `state.…` 변수와 DOM 조작은
"서버에서 읽어야 할 데이터"로 번역해 적는다.

### 프로토타입 CSS의 색과 글자 크기는 쓰지 않는다

- 프로토타입 분홍 `#FF4E74` → 흰 글자 대비 3.18:1, **WCAG AA 미달**
- 프로토타입 기준 글자 13.5px → 시니어에게 너무 작다 (우리는 17px)

가져오는 것은 **여백·모서리·그림자·배치·구조·비율**이다.
`globals.css` 머리말에 이 판단의 근거가 적혀 있다.

## 명세로 옮길 때

원본을 그대로 붙여넣는 건 명세가 아니다. 아래를 **해석해서** 적는다:

1. **골격** — 앱바 / 본문(스크롤) / 액션바(고정) 3단인가? 고정과 스크롤을 구분해 적어라.
2. **필요한 데이터** — 이 화면을 그리려면 무엇이 있어야 하는가. 서버 쿼리의 입력이 된다.
3. **부품** — 반복되는 덩어리. 지금 앱에 있는 것과 새로 만들 것을 나눠라.
4. **뺀 것** — 버림 판정된 항목을 근거와 함께. 나중에 "왜 없지?"를 막는다.
