# 오늘도 사랑해

소중한 존재(가족·연인·나 자신·반려동물 등)에게 마음을 전하고 싶지만 표현을 시작하기 어려운 사람을 위한 프로젝트다. 2026-09-28 사용자가 대상을 '가족'에서 넓혔고, 사전 인터뷰·사용자 테스트는 가족에게 표현하는 경험에 집중한다. 아이디어와 기획 의도는 사용자 본인의 경험에서 출발했으며, 발전 과정에서 팀원들과 논의했다는 사용자 진술을 기록했다.

**현재 목표는 포트폴리오 완성이다.** 2026-09-22 사용자 결정에 따라 브라우저 데모를 중심으로 하고 안드로이드 앱은 보조 자료로 둔다. 대상 Supabase 프로젝트는 `wdzzianhfnupmfbjqqac`다. 사용자 승인으로 DB 변경문 5개를 적용하고 [기존 앱](https://iloveyoutodaytoo.vercel.app)을 운영 배포했다. 적용 후 `public` 테이블 24개·Storage 버킷 6개를 확인했다. **신규 가입은 Auth와 앱 화면 양쪽에서 비활성화 상태다.** 공개 경로·빌드, 모바일 모의 Chrome의 합성 사진 추억·반응·댓글·답글·공개 전환·정상 탈퇴, 운영 DB의 탈퇴 파일 삭제 실패·재시도를 확인했다. 최종 원격 집계는 계정·방·삭제 작업·Storage 객체 모두 0건이다. 실제 기기·촬영·녹음·영상과 개인정보 처리방침의 운영 정보는 미확인이다. [E22 검토 기록](문서/인수인계/2026-09-28_E22_개인정보와_함수권한_검토.md)·[E23 운영 기록](문서/인수인계/2026-09-28_E23_가입대기와_탈퇴파일_재시도.md).

2026-09-28 사용자는 **카카오 로그인·가입을 첫 인증 방식**으로 선택했다. 운영자·보호책임자·문의 이메일·시행일은 아직 미정이라 가입 차단을 유지한다. 생년월일·미성년 가입 정책과 카카오 OAuth의 충돌, 필요한 설정은 [E24 인수인계](문서/인수인계/2026-09-28_E24_카카오_첫인증_가입대기_설계.md)에 정리했다. 카카오 인증 구현·활성화는 아직 아니다.

**최신 E25 답변:** 포트폴리오 범위로 좁혀 **카카오·네이버 로그인/회원가입을 철회**했다. 14세 미만 허용은 UI 시안에서만 표현하며 실제 가입은 계속 닫혀 있다. 참여자용 데모에는 가입 단계가 없어 시안의 위치·표현 범위를 [E25 인수인계](문서/인수인계/2026-09-28_E25_포트폴리오_가입화면범위_재결정.md)에 선택 대기로 남겼다. 위 E24 문장은 당시 결정 기록이다.

2026-09-25 사용자는 음성의 ‘3초 이상’ 조건을 데모뿐 아니라 기존 Supabase 연동 앱의 추억·댓글·사서함에서도 제거하도록 범위를 확인했다. 앱 코드와 원격에 적용한 초기 마이그레이션은 0~60초를 허용한다. 실제 마이크·업로드 사용은 아직 확인하지 않았다. [변경 범위와 잔여 검증](문서/10_최신변경_잔여점검.md)을 참고한다.

**이 README가 프로젝트의 입구이고, [PLAN.md](PLAN.md)가 현재 계획이다.** 작업을 이어갈 때 PLAN의 목표·범위·확인 지점을 읽고, [개인비서용 기록](/Users/b/Documents/개인비서/자료함/프로젝트/오늘도사랑해/README.md)에서 본인 기여·사용자 결정·실제 검증 상태를 대조한다.

2026-09-28 최신 조사 방식은 20~30대 3~5명과 직접 인터뷰하는 50대 1명에게 [첫 설문 → 데모 → 후기 → 합쳐 복사](https://oneuldo-demo.vercel.app/demo/pre-survey)를 제공하는 것이다. 50대 참여자는 진행자가 첫 답변을 듣고 대신 입력할 수 있다. 실제 답변 수신·화면 관찰은 아직 없다. [남은 작업 실행판](문서/19_PLAN_남은작업_실행판.md)과 [포트폴리오 사례 초안](문서/22_포트폴리오_사례초안.md)에서 근거 범위를 확인한다. [역질문 화면](문서/21_PLAN_역질문.html)은 앞선 선택 과정의 기록이다.

역질문 여섯 항목의 첫 사용자 답변은 [사용성 테스트 진행안](문서/23_사용성테스트_진행안_결정반영.md)에 반영했다. 당시 “몇명은 구글폼, 몇명은 설문지”가 애매했으나, 아래 후속 답변으로 진행 방식을 확인했다.

사용자는 앞서 사용성 구글폼을 만들었다고 밝혔지만, 이후 **데모 화면 밖 버튼 → 내부 7문항 → 답변 복사 → 직접 전달**로 방식을 바꿨다. [현재 진행안](문서/25_데모내_후기설문_복사전달_진행안.md)을 따른다. 옛 [구글폼 구성안](문서/24_사용성테스트_구글폼_구성안.md)은 이력으로 보존한다. 실제 화면 조작은 직접 관찰하지 않으며, 복사만 한 답변은 수신 응답으로 세지 않는다.

이 후기 설문은 [공개 데모](https://oneuldo-demo.vercel.app/demo)의 체험 화면 밖에서 열 수 있다. [설문 주소](https://oneuldo-demo.vercel.app/demo/feedback)의 7문항·복사 동작은 배포본 격리 Chrome에서 확인했다. 참가자가 복사한 내용을 직접 보내야 답변이 전달된다. 실제 기기·참가자 응답은 아직 확인하지 않았다.

2026-09-26부터 인터뷰안 이외의 남은 작업과 새 DB·추억 영상의 로컬 구현은 [Claude 연속 실행 지시서](문서/12_클로드_연속실행_지시서.md) 및 [첫 세션 인수인계](문서/인수인계/2026-09-26_시작.md)를 시작점으로 삼는다. 기존 인터뷰 세션의 질문 작업과 파일은 별도다. 지시서 작성은 구현·원격 적용·배포의 완료 근거가 아니다.

**2026-09-25부터 PLAN의 문제 확인 단계를 진행한다.** 사용자는 중요한 방향·의도·충돌을 임의로 정하지 말고 역질문하도록 요청했다. 사전 인터뷰 질문은 사용자가 먼저 만들어 보고 Codex와 다듬는다. 섭외·인터뷰는 사용자가 직접 진행하며, Codex는 피드백·자료 정리·결과 정리를 맡는다. 실제 인터뷰·구현·배포의 완료 여부는 각각의 근거로 판단한다.

현재 저장소에는 기존 Next.js·Supabase 연동 코드와 안드로이드 프로젝트, 서버 연결과 분리한 `/demo`가 있다. 데모는 브라우저 저장으로 작성·재생·반응을 체험한다. 대표 시안 A를 선택해 데모 전용 주소에 배포했고 E6까지 자동 검사를 했다. 실제 기기·참가자 검증은 아직 완료하지 않았다.
