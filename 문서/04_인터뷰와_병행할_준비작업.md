# 인터뷰와 병행할 준비 작업 — 현재 후보와 의존관계

기준일: 2026-09-25. [PLAN](../PLAN.md) 5절은 사전 인터뷰를 기다리는 동안 화면 목록·상태 설계·검증 문서를 준비하도록 한다. [현재 데모 화면·상태 목록](03_데모_현재흐름과_상태목록.md)은 코드 읽기로 이미 작성했다. 아래는 다음 병행 작업의 **선택지와 의존관계**이며, 사용자 우선순위나 해결 방향을 확정한 문서가 아니다.

| 병행 후보 | 지금 준비할 수 있는 산출물 | 인터뷰·사용자 판단 뒤 정할 것 |
|---|---|---|
| 화면 흐름·상태 설계 점검 | 현재 데모의 진입 → 가족방 → 작성 → 상세 → 다시 보기와 빈 상태·실패·복귀를 [화면 목록](03_데모_현재흐름과_상태목록.md) 및 코드에 대조하고 빠진 상태를 표시 | 어떤 어려움을 해결할지, 화면·문구·기능을 어떻게 바꿀지 |
| 사용자 테스트 과업·기록 틀 준비 | [PLAN의 과업](../PLAN.md)과 기존 인터뷰 기록 틀을 기준으로 관찰 항목·도움 제공·실패 기록 위치를 설계 | 실제 과업 문구, 평가 기준, 참여자에게 보여줄 화면과 테스트 일정 |
| 대표 화면 시안 비교 준비 | 기존 로고·색·카드 결정과 홈·작성·상세의 현재 모습을 모아 비교 기준을 정리 | 두 시안의 구체적 배치·문구, 대표안 선택, 전체 화면 적용 |

**사용자 선택:** 화면 흐름·상태 설계 점검을 첫 병행 작업으로 선택했다. [코드 읽기 결과와 남은 설계 질문](05_데모_흐름과_상태_점검.md)을 작성했다. 이어 사용자 테스트 **관찰 기록 틀**을 다음 병행 작업으로 선택했고, [빈 과업·관찰 기록 양식](07_사용자테스트_과업과_관찰기록_틀.md)을 준비했다. 실제 코드 변경·브라우저 검증·참여자 테스트·시안 확정은 이 문서 작업에 포함하지 않았다.

사용자는 인터뷰안과 PLAN의 다른 일을 병행하고 싶다고 밝혔다. 앞의 두 작업 뒤 “다음 작업 ㄱㄱ”라고 했고, Codex는 남은 병행 후보인 **대표 화면 비교 준비**를 뜻하는 것으로 해석해 [자산·기준·검토표](08_대표화면_비교준비.md)를 작성했다. 실제 두 시안의 제작·선택은 별도 단계다.

## 2026-09-25 현재 병행 가능성 재점검 — 당시 AI 판단과 후속 사용자 선택

현재 다른 세션은 [인터뷰 진행안](02_사전인터뷰_진행안.md)의 질문을 사용자와 다듬는 중이다. 화면 담당 세션은 [데모 흐름·상태 점검](05_데모_흐름과_상태_점검.md)을 **코드 읽기 범위에서 완료**했다. 이 완료는 화면 설계 확정이나 브라우저 검증 완료가 아니다.

| 남은 작업 | 인터뷰와 병행 가능한 범위 | 기다려야 할 판단·실행 |
|---|---|---|
| 사용자 테스트 과업·관찰 기록 틀 | [PLAN 4절](../PLAN.md)의 작성 → 열람·반응 → 다시 보기 과업에 대해 참여자 식별자, 기기·브라우저, 도움 여부, 오류, 실제 행동·발언을 적을 **빈 양식**을 준비할 수 있다. 사전 인터뷰 질문지는 다른 세션 소유이므로 수정하지 않는다. | 인터뷰 결과에 맞춘 최종 과업 문장·관찰 기준, 참여자 일정과 실제 테스트는 이후에 정한다. |
| 대표 화면 비교 준비 | 기존 [디자인 기준](../design/DEMO_REVIEW.md)과 홈·작성·상세의 현재 화면을 모아 비교 기준과 확인할 차이를 정리할 수 있다. | 구체적인 두 시안의 문구·배치, 대표안 선택과 전체 적용은 인터뷰 결과와 사용자 화면 검토 뒤에 정한다. |
| 합의된 뒤로 가기·녹음 이탈 동작 | [점검 문서](05_데모_흐름과_상태_점검.md)에 목표 동작과 현재 코드의 차이가 기록돼 있어 후속 구현 범위를 추적할 수 있다. | PLAN 4단계의 구현과 5단계의 브라우저·실기기 검증은 해결 방향·시안 검토 흐름에 맞춰 진행한다. 이번 병행성 점검은 코드 변경 승인이 아니다. |
| 사용자 문제·해결 방향·배포·효과 판단 | 현재 자료와 미확인 항목을 목록화할 수 있다. | 실제 인터뷰, 사용자 선택, 구현·기술 검증, 참여자 관찰 없이는 확정하거나 완료로 표시할 수 없다. |

**당시 추천과 후속 실행:** Codex는 사용자 테스트 과업·관찰 기록의 빈 틀을 추천했고, 사용자가 “ㄱㄱ”로 이 준비 작업을 선택했다. [양식](07_사용자테스트_과업과_관찰기록_틀.md)에는 PLAN의 과업 순서와 행동·도움·오류·실제 발언의 기록 칸을 두었다. 최종 과업 문구·완료 조건·테스트 환경·일정은 미확정이고, 참여자 테스트·시안 작성·코드 수정·브라우저 검증은 `NOT_RUN`이다.

**후속 준비:** [대표 화면 비교 준비](08_대표화면_비교준비.md)에 기존 로고·색·카드 결정, 홈·작성·상세의 코드상 구성, 두 안에서 비교할 배치·밀도와 사용자 검토 칸을 모았다. 이는 자료 정리 완료이며 현재 화면 캡처·두 시안 제작·사용자 선택·구현·새 브라우저 검증은 `NOT_RUN`이다.
