## 2단계: 해결 방향 비교 — 선택 전 검토 자료

| 대안 | 예상 도움 | 반례·비용 | 현재 증거 |
|---|---|---|---|
| 지금 쓰는 전화·메시지를 더 쉽게 쓰기 | 새 서비스 학습이 없고 전달이 빠름 | 마음을 남기고 다시 보는 목적에는 부족할 수 있음 | 실제 참여자의 기존 방법·막힘 미수집 |
| 손글씨·목소리·사진·영상 중 고르게 하기 | 표현을 시작할 수단을 선택할 수 있고 기록을 다시 볼 수 있음 | 수단 선택 자체가 부담이거나 촬영·권한·저장 실패가 생길 수 있음 | 데모 구현과 자동 검사는 있음; 부담 감소는 미검증 |
| 질문 카드·알림으로 계기 주기 | 무엇을 쓸지 막힐 때 시작 단서를 줄 수 있음 | 원치 않는 알림·상투적인 질문이 부담을 늘릴 수 있음 | 사용자 요청·실제 문제 근거 없음; 구현 보류 |

판단 기준: 최근 실제 표현 장면과 망설인 이유, 기존 방법이 충분했던 반례를 먼저 확인한다. 방법 선택의 어려움인지 표현 계기의 부족인지 드러나지 않으면 기능 효과를 단정하지 않는다.

## 2~5단계: 현재 데모의 핵심 흐름과 확인점

1. 소개 → 홈 → 앨범방: 가입 없이 진입한다. 홈의 새 앨범방 아이콘은 현재 한 방만 지원하는 데모에서 안내창을 띄운다. 이 기능의 사용자 기대와 충돌할 수 있어 선택 대기.
2. 앨범방의 `+` → 작성: 손글씨·목소리·사진·영상 중 고른다. 다른 수단으로 옮겨도 초안은 유지된다. 작성 중 녹음 이탈은 확인 후 버리고, 영상 촬영 이탈은 사용자 결정대로 바로 버린다.
3. 저장 → 상세: 저장 성공 후 상세로 이동한다. 실패하면 초안을 남긴다. 목록에서 다시 열어 읽고, 재생·좋아요·댓글을 쓴다. 반응과 본인 기록 수정·삭제·앨범방 편집은 데모 안의 동작이다.
4. 브라우저 저장소: 같은 브라우저에서 다시 볼 수 있다. 실제 상대에게 전송되거나 다른 기기에 동기화되지는 않는다. 역할 전환은 데모 조작이며 실제 가족의 반응 근거가 아니다.
5. 기술 점검의 남은 범위: 실제 휴대전화 브라우저의 마이크·영상 촬영/업로드·터치·글자 확대, 저장 공간 부족·권한 거부·새로고침 복귀. E6 자동 검사를 실기기 검사로 표시하지 않는다.

## 6단계: 진행 전에 사용할 기록 규칙

- 참가자별 익명 ID, 데모 버전, 사용 기기, 화면 사용 확인 방식, 도움 제공, 과업 결과를 기록한다. 설문 응답과 직접 관찰을 분리한다.
- 과업은 작성(T1), 예시 열람·반응(T2), 자기 기록 다시 찾기(T3) 순서의 초안이다. 실제 읽을 문장과 완료 조건은 사용자 확정 대기다.
- 실제 가족 내용을 강요하지 않는다. 가상의 짧은 내용으로 바꾼 결과는 화면 사용으로만 센다. 진행자가 상대 역할로 반응한 것은 실제 상대의 반응으로 세지 않는다.
- 개선은 관찰된 반복 막힘을 근거로 우선순위를 정한 뒤 진행한다. 결과 없는 개선 수치·성공담은 쓰지 않는다.

## 7단계: 포트폴리오 문장 초안의 증거 경계

| 쓸 수 있는 문장 | 근거 | 아직 쓸 수 없는 문장 |
|---|---|---|
| 사용자 본인의 어머니와의 경험에서 표현의 시작이 어렵다는 문제 가설을 세웠다. | 사용자 직접 진술, 개인비서 원본 기록 | 대상자 다수가 같은 문제를 겪었다 |
| 대표 시안 A를 사용자가 선택했고, AI가 데모 화면과 기능을 구현했다. | 디자인 결정·E/E2~E6 인수인계 | 최신 E6 화면을 사용자 테스트에서 선호했다 |
| 가입 없는 브라우저 데모를 공개했고, 자동 시나리오 37/37이 E6 당시 통과했다. | F/E6 인수인계·검사 결과 | 실제 기기와 5명이 오류 없이 사용했다 |
| 앱의 새 DB·영상은 로컬 합성 검사와 화면 검사까지 진행됐다. | A/E3 인수인계 | 원격 DB 적용·실제 가입·기기 사용 완료 |

실제 응답·관찰·개선 전후 결과는 빈칸으로 유지한다. 기존 팀원이 맡은 세부 역할은 출처를 확인한 것만 적고, AI가 나중에 만든 이유를 사용자의 당시 의도로 바꾸지 않는다.
