# 사용자 테스트 과업·관찰 기록 틀 — 사용 전 초안

기준일: 2026-09-25. 사용자가 인터뷰안 작성과 병행할 다음 작업으로 **관찰 기록 틀 준비**를 선택했다. [PLAN 4절](../PLAN.md)과 [데모 흐름 점검](05_데모_흐름과_상태_점검.md)을 바탕으로 만든 **빈 양식**이다. [화면을 보여주기 전 사전 인터뷰](02_사전인터뷰_진행안.md)의 질문·기록과 역할이 다르다. 실제 참여자 테스트와 결과 분석은 `NOT_RUN`이다.

**2026-09-28 참여 방식 추가:** 사용자는 어머니를 포함해 5명이 사용성 테스트에 참여 가능하며 구글 설문을 함께 쓰겠다고 밝혔다. 이 설문은 1단계의 [최신 문제 확인 설문 프롬프트](18_공동작성_인터뷰안_기반_구글폼_프롬프트.md)와 목적을 구분해야 한다. [사용성 설문 초안](20_사용성테스트_설문_초안.md)은 문항 제안이며 시점·내용은 미정이다. 실제 참여·데모 사용·설문 응답은 아직 없고, 1단계 세 명과 테스트 참여자의 중복 여부도 미확인이다. 설문 응답만으로 도움 없이 완료했는지, 어디서 막혔는지를 관찰했다고 기록하지 않는다.

## 사용 전 확정할 것

- 사전 인터뷰 결과를 본 뒤 해결 방향, 보여줄 데모 버전, 최종 과업 문장과 **과업별 완료 조건**을 사용자와 정한다. 아래 과업 설명은 관찰 항목을 준비한 것이며 참가자에게 읽을 확정 문구가 아니다.
- 참여자에게 화면을 보여주는 시점, 과업 순서, 진행자가 언제 도움을 주는지, 상대 인물 역할을 언제 대신하는지 정한다. 화면을 보여주기 전 인터뷰는 다른 세션의 [진행안](02_사전인터뷰_진행안.md)을 따른다.
- 데모를 실제로 어떻게 사용했는지 확인할 방식과 구글 설문을 제출할 시점·내용을 정한다. 실시간 조작 관찰이 어렵다면 자기 보고 응답을 관찰된 행동으로 바꾸지 않고, 확인 가능한 범위를 따로 적는다.
- **확인된 대체 방식:** 실제 가족에게 쓸 사적인 내용이 부담스럽다면 가상의 짧은 내용으로 작성 조작을 계속할 수 있다. 이 경우 화면 사용 결과와 실제 마음 표현 경험을 구분한다. 참여자에게 어떻게 안내할지는 최종 과업 문구를 정할 때 함께 검토한다.
- 테스트 링크·기기·브라우저에서 핵심 흐름이 열리는지 별도의 기술 검사를 마친 뒤 실제 참여자에게 사용한다. 검사 미완료나 실패를 참가자의 사용성 문제로 합치지 않는다.
- 메모와 녹음·녹화·인용 동의는 각각 확인한다. 공유 문서에는 실명·연락처·실제 가족의 사적인 글·사진·음성을 그대로 넣지 않는다.

## 과업 순서 초안

| ID | 참가자에게 맡길 행동의 범위 | 관찰할 점 |
|---|---|---|
| T1 작성 | 가족 한 명을 떠올리고 마음을 남긴다. 표현 수단과 조작 순서는 먼저 알려주지 않는다. | 앨범방·작성 진입, 첫 수단 발견, 입력·전환·저장, 막힘과 도움, 저장 결과 이해 |
| T2 열람·반응 | 예시 마음을 찾아 열고 읽거나 재생한 뒤 반응한다. | 목록에서 찾기, 재생·읽기, 반응 버튼의 의미, 진행자의 역할 전환·도움 |
| T3 다시 보기 | 방금 본인 이름으로 남긴 기록을 다시 찾는다. | 복귀 경로, 목록 탐색, 동일 기록 재열람, 기억에 의존한 우회·도움 |
| 마무리 비교 | 평소 연락 방법과 이 체험의 편함·부담, 쓸 상황과 쓰지 않을 이유를 듣는다. | 참여자 발언의 구체적 상황과 반례. 호감 표현만으로 가치가 확인됐다고 쓰지 않음 |

T1에서 가상 내용으로 바꾼 경우에도 참여자가 원치 않는 행동을 계속 요구하지 않는다. 가상 내용의 저장·재열람 성공은 **화면 조작 관찰**로 기록하며, 실제 가족에게 마음을 표현할 수 있었거나 그 가치가 확인됐다는 근거로 쓰지 않는다.

녹음 권한 거부·저장 실패·잘못된 주소 같은 상태는 발생하면 기록한다. 의도적으로 재현하는 기술 검사는 [PLAN의 기술 확인](../PLAN.md)에서 따로 설계한다. 진행자가 상대 역할로 누른 반응은 **실제 가족의 반응이 아니다.**

## 여러 세션을 모을 때

과업별 `n/N`은 **실제 그 과업을 시작한 N명 중 사전에 정한 조건을 도움 없이 마친 n명**으로 적는다. 도움 완료·미완료·기술 중단·미시도 인원도 각각 표시한다. 완료 조건이 아직 없거나 실제 기록이 없으면 비율을 계산하지 않는다. **참여 가능 인원 5명은 실제 참여·관찰한 `N=5`가 아니다.** 설문 응답 수와 과업 조작을 확인한 인원도 따로 센다.

T1은 실제 내용·가상 내용·중간 전환의 시도와 완료를 별도로 확인한다. 가상 내용으로 마친 사람을 T1의 화면 조작 완료에는 포함할 수 있지만, 실제 마음 표현이나 가치 확인의 완료로 합산하지 않는다. 완료 조건은 테스트 전에 정한다.

| 과업 | 무도움 완료 n / 시도 N | 도움 완료 | 미완료·참여자 중단 | 기술 중단 | 미시도·조건 차이 |
|---|---|---|---|---|---|
| T1 작성 | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN |
| T2 열람·반응 | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN |
| T3 다시 보기 | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN | NOT_RUN |

- 반복된 막힘: 관찰 근거 __ / 다른 설명 __ / 개선 후보와 사용자 판단 __
- 반례·도움이 없었던 상황: __
- 수정 뒤 재확인한다면: 변경 전후 버전·과업·기기·참여자 동일 여부 __ / 학습 효과 __ / 실제 결과 __
- 이번 자료로 말할 수 없는 것: 실제 가족의 반응, 관계 개선, 지속 사용 효과, 시장 전체의 수요.

**현재 상태:** 양식 작성만 완료. 최종 과업 문장·완료 조건·참여자 일정·데모 버전 확정, 실제 테스트, 집계, 개선·재검증은 모두 `NOT_RUN` 또는 미확정이다.
