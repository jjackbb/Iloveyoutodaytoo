## 실제 앱 로컬 이식

| 기능 | 실제 앱 변경 |
|---|---|
| 손글씨 | 필기구 3종·편지지 2종 선택을 작성·수정에 연결하고 획 재생에 반영. 기존 획 JSON은 그대로 두고 선택 값만 추억 행에 저장 |
| 영상 | 8칸 장면 줄, 시작·끝 손잡이, 대표 장면 선택. 원본 파일은 다시 인코딩하지 않고 구간·장면 시점만 저장. 피드·상세 재생에서 지정 구간을 지킴 |
| 마음 표현 | 기존 하트는 `memory_likes` 유지. 고마워요·힘내요·보고싶어요는 새 `memory_reactions`에 사람·종류별로 저장. 상세에서 [+]를 왼쪽에 두고 누군가 누른 표현만 한 줄로 표시. 피드 카드는 데모와 같이 하트·댓글 수를 유지 |
| 답글 | 댓글을 0.5초 길게 누르거나 키보드 Enter·오른쪽 클릭으로 대상 선택. 원 댓글 아래 한 단계로 표시하고 DB가 다른 게시물·답글에 답글을 달지 못하게 검사. 텍스트 답글만 지원 |
| 화면 | 작성 방법 2×2 흰 타일, 상세 게시물·댓글 흰 카드, 손글씨 ▶ 다시 재생, 편집 하단 [취소][저장하기] 반반. 녹음 중 취소는 확인 |

DB 변경문은 `frontend/supabase/migrations/20260928000001_memory_expression.sql`이다. 기존 추억은 기본 필기구·편지지와 영상 전체 구간으로 읽도록 기본값을 둔다. `frontend/src/types/database.ts`와 앱 서버 액션·조회·부품을 함께 갱신했다.

## 확인한 것과 남은 것

- **통과:** 실제 앱 TypeScript, 변경 파일 ESLint, `next build --webpack`. Git diff 공백 검사.
- **미실시:** 새 SQL의 로컬/원격 DB 실행, DB 권한·RLS 실동작, 실제 앱 브라우저·휴대폰 조작, 기존 앱 배포. 기본 Turbopack 빌드는 최적화 단계에서 오래 멈춰 중단했고 webpack 빌드로 확인했다. 이전 데모 43/43은 이 앱 기능의 동작 검사가 아니다.
- **운영 경계:** 이 워크트리의 `frontend/.env.local`은 `127.0.0.1`을 가리킨다. 프로젝트 전용 Supabase 연결 도구·CLI·실행 중인 로컬 DB를 확인하지 못했다. 설치된 `supabase_thinkerbell` 도구는 다른 프로젝트용이라 사용하지 않았다. E3 절차에는 새 프로젝트 참조 `wdzzianhfnupmfbjqqac`와 초기 두 마이그레이션 적용이 필요하다고 기록되어 있다. 이번 E19 SQL은 그 뒤에 온다.
- **참여 흐름:** 사용자 최신 요청은 20~30대 3~5명과 직접 인터뷰하는 50대 1명을 한 흐름으로 묶어, 첫 설문 → 데모 → 후기 설문 → 답변 합쳐 복사·직접 전달하는 것이다. 실제 Google Form의 최종 질문·분기·동의 문안이 제공되지 않아 데모 통합 화면은 만들지 않았다. 기존 후기 설문은 그대로다.
- **댓글 예외:** 원 댓글이 지워져 답글만 남으면 현재 앱은 답글을 단독으로 보이며 원 댓글 삭제를 안내한다. 사용자가 원하는 최종 표시 방식은 확인 대기다.

## 다음 결정

1. 실제 앱 반영 요청이 원격 DB 마이그레이션과 기존 앱 운영 배포까지 포함하는지, 또는 이번처럼 코드·SQL을 브랜치에 준비하는 범위인지 확인한다. 운영 적용 시 E3의 초기 DB 적용 여부와 실제 대상 프로젝트를 먼저 검증한다.
2. 실제 Google Form 주소 또는 최종 문항·분기·동의 문안을 받아 데모 내부 첫 설문과 합쳐 복사하는 흐름을 구현한다. 50대 직접 인터뷰 입력 경로도 같은 문항으로 설계한다.
3. 삭제된 원 댓글 아래 답글을 어떻게 보일지 확인한다. 현재 방식은 안전한 임시 표시이며 운영 적용 전 결정한다.
