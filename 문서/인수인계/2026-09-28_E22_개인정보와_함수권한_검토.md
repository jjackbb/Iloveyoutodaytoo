# E22. 개인정보 문서·운영 함수 권한 검토

- **대상:** 작업 브랜치 `worktree-db-video-local`, 운영 Supabase `wdzzianhfnupmfbjqqac`, 기존 앱 <https://iloveyoutodaytoo.vercel.app>
- **범위:** 실제 코드·운영 설정과 공개 개인정보 처리방침·약관을 대조하고, 운영 DB의 `SECURITY DEFINER` 실행 권한을 점검했다. 법률 전문가의 확정 의견이나 실제 사용자·실기기 관찰을 대신하지 않는다.
- **보호 상태:** 신규 가입은 Supabase Auth에서 계속 비활성화했다. 기존 앱의 가입 화면은 보이지만 신규 계정 생성은 허용하지 않는다.

## 확인과 수정

1. 앱은 가입 때 이름·아이디·생년월일·비밀번호를 받고, 아이디에서 만든 내부 이메일 형식의 식별자로 Supabase Auth에 가입한다. 실제 이메일은 받지 않는다. 만 14세 미만은 보호자 입력 없이 서버와 DB에서 차단한다. 기존 문서의 이메일 필수·보호자 정보 수집 문구를 실제 동작에 맞게 고쳤다.
2. 앱은 가입 후 프로필 사진과 앨범방의 사진·영상·손글씨·음성, 댓글·반응, 푸시·위젯 정보를 처리한다. 기존 문서의 “사진·영상 기능 없음”, “프로필 사진 없음” 문구를 고쳤다. 다만 각 항목의 정확한 보유 기간·공유 범위는 운영 전 추가 검토가 필요하다.
3. 탈퇴는 DB의 인증 계정·가입 정보를 삭제한 뒤 Storage 파일을 별도로 지운다. 파일 목록 조회·삭제 실패는 로그만 남기고 탈퇴를 되돌리지 않는다. 기존 문서의 모든 파일을 즉시·영구 삭제한다는 단정을 제거하고 실패 시 후속 정리 필요성을 적었다. 합성 사진 한 장이 있는 시험 계정의 정상 탈퇴 경로는 아래와 같이 확인했지만, 삭제 실패·재시도 경로는 확인하지 않았다.
4. `CONTACT_EMAIL`은 빈 문자열이라 `/my/contact`는 권리 행사 접수 기능이 없다. 운영자명·보호책임자·연락처·시행일도 미정이다. 국외 이전의 법적 근거, Vercel의 처리 국가·연락처·보존 기간과 Supabase/Vercel 로그·백업 기간도 확인되지 않았다. 문서에는 확인 필요 상태를 표시했다. 이용약관의 공지·개별 통지 약속도 현재 경로가 없는 상태에 맞춰 고쳤다.
5. Supabase 프로젝트 리전은 서울이다. 이것만으로 모든 위탁 처리·백업·접속 로그가 국내에만 머문다고 결론 내리지 않았다. Vercel의 [처리계약](https://vercel.com/legal/dpa)은 미국과 다른 운영 지역의 처리를 설명하지만, 실제 계정 플랜·하위 처리자·설정에 따른 고지 항목은 별도로 확정해야 한다.

개인정보 처리방침의 필수 기재 항목과 실제 처리의 일치는 [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029331583) 및 [개인정보보호위원회 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=G010030030&nttId=12018)을 기준으로 검토했다. 국외 이전 고지 항목은 [같은 법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034292881)를 참고했다.

## 운영 DB 권한

- 적용 전 `public` 스키마에 `SECURITY DEFINER` 함수 41개, `anon` 실행 가능 31개, `authenticated` 실행 가능 36개였다. Supabase 보안 조언의 경고 67건은 역할별 경고 수이며, 취약점 67개라는 뜻은 아니다.
- 로그인 뒤에만 쓰는 비트리거 함수 15개의 `PUBLIC`·`anon` 실행 권한을 새 변경문 `20260928000002_function_acl.sql`에서 회수했다. 로컬 DB 거래에서 적용 후 `대상 15 / anon 0 / authenticated 15 / service_role 15`를 확인하고 되돌렸다. 대상 프로젝트 미리보기에서 이 변경문 한 개만 표시된 뒤 원격 적용했다. 원격 변경 이력 1개와 같은 권한 결과를 다시 확인했다.
- 적용 후 `anon` 실행 가능 함수는 16개다. 이 중 12개는 트리거 함수이고, 비트리거 4개는 초대 미리보기, 아이디 중복 확인, 위젯 토큰 조회·알림용으로 공개 호출이 필요한 함수다. `authenticated` 실행 가능 함수는 36개다. 트리거·로그인 함수에도 보안 조언이 남을 수 있으므로 경고가 모두 해결됐다고 표시하지 않는다. [Supabase 함수 보안 안내](https://supabase.com/docs/guides/database/functions)와 [API 보안 안내](https://supabase.com/docs/guides/api/securing-your-api)를 참고했다.

## 로그인·기기 검증

- 신규 가입을 열지 않고 관리자 경로로 무작위 내부 식별자 시험 계정을 만들었다. 격리 Chrome에 모바일 화면·앱 User-Agent를 설정해 운영 앱 로그인 → 홈 → 앨범방 만들기를 확인했다. 시험 방과 계정을 삭제한 뒤 원격에서 `auth.users=0`, `rooms=0`, `memories=0`, `user_private=0`을 읽어 확인했다.
- 추가 시험에서 모바일 모의 Chrome으로 합성 사진 추억 작성 → 상세 조회 → ‘고마워요’ 반응 → 댓글 → 한 단계 답글 → 나만 보기에서 앨범방 공개 전환을 확인했다. 운영 DB에서 추억 1건의 `visibility=room`, 사진 1건·반응 1건·댓글 2건을 읽었다. 이때 시험 스크립트의 첫 Storage 정리 요청은 경로를 잘못 써 400이었고, [공식 Storage API 방식](https://supabase.com/docs/guides/storage/management/delete-objects)으로 남은 합성 사진 1건을 지운 뒤 재조회 0건을 확인했다. 앱 기능 실패로 분류하지 않는다.
- 별도 시험에서는 합성 사진 추억 1건이 있는 계정으로 앱의 **회원 탈퇴**를 완료했다. 화면에 완료 안내가 나왔고, 이후 Auth 계정 조회는 404, 시험 방·추억·Storage 사진은 각 0건이었다. 최종 원격 집계도 Auth 사용자·방·추억·댓글·Storage 객체 모두 0건이다. 정상 경로 한 사례만 확인한 결과다.
- 이 검사는 모두 **모바일 모의 브라우저와 합성 파일**에서 했다. 실제 Android/iOS 기기, 카메라·마이크, 영상 구간·대표 장면, 초대와 두 사람 간 공유, 파일 삭제 실패 후 처리, 실제 사용자 조작은 확인하지 않았다. 연결된 Android 기기는 없었고 iOS 시뮬레이터도 사용할 수 없었다.
- Auth 이메일 확인은 켜져 있다. 실제 이메일을 받지 않는 가입 방식에서는 사용자가 확인 메일을 받을 수 없으므로, 가입 개방 전 설정을 맞춰야 한다. 지금은 신규 가입 비활성화 상태를 유지했다.

## 공개 문서 배포

- E22 코드·문서 커밋 `4b13ca1`을 작업 브랜치에 푸시했다. 추적된 `frontend` 파일만 임시 배포 묶음에 넣어 기존 앱 Production에 배포했다. 첫 시도는 프로젝트의 `frontend` 루트 설정과 묶음 구조가 달라 빌드 전에 실패했다. 구조를 고친 두 번째 배포 `dpl_Aqid9gNZsZ4q8qWrSmtNtVJwyG8U`는 `READY`로 운영 주소에 연결됐다.
- 두 번째 배포의 Next 빌드·TypeScript·정적 페이지 생성이 통과했다. 운영 주소의 `/legal/privacy`, `/legal/terms`가 모두 HTTP 200이고 정정한 이메일·만 14세 미만·문의 창구·공지 문구가 포함된 것을 확인했다. 신규 가입 설정은 이 배포에서 변경하지 않았다.

## 가입 개방 전 결정·작업

1. 운영자명, 공개 연락처, 개인정보 보호책임자, 시행일과 문의 접수 경로를 확정하고 실제 화면에 연결한다.
2. 로그·백업 보존 기간, Vercel의 처리 국가·연락처·국외 이전 근거와 거부 방법, Storage 삭제 실패 후 처리 절차를 확정한다. 그 결과를 개인정보 처리방침과 약관에 반영한다.
3. 내부 식별자 방식과 이메일 확인 설정을 맞춘 뒤 실제 **가입**, 실기기 촬영·녹음·영상과 초대·두 사람 간 공유를 검사한다. 합성 사진이 있는 계정의 정상 탈퇴는 한 번 통과했으나 파일 삭제 실패 경로는 별도다. 사용자가 가입 개방을 결정하기 전까지 Auth 신규 가입은 꺼 둔다.
