# E25. 포트폴리오 범위와 가입 화면 재결정

- **사용자 직접 답변:** “포트폴리오 까지만 구현할거니까, 14세 미만도 허용하고, ui 적으로만 표현.” 카카오·네이버 로그인/회원가입은 철회했다.
- **이번 범위:** 포트폴리오용 **화면 표현**. 카카오·네이버 인증 연동, 임시 Auth 신원, 보호자 인증, 실제 미성년자 가입 개방을 구현하지 않는다. E24의 카카오 첫 인증 선택과 설계 질문은 이 답변으로 종료됐다.
- **운영 사실:** 기존 앱 `/signup`은 가입 준비 중 안내다. Supabase Auth 신규 가입은 E23 확인 당시 비활성화 상태였고 이번 작업에서 설정을 바꾸지 않았다. 현재 DB의 14세 미만 가입 차단도 바꾸지 않았다. “14세 미만 허용”은 포트폴리오 시안의 의도이며 실제 서비스 가입 가능 상태를 뜻하지 않는다.

## 화면을 만들기 전 확인한 충돌

- 현재 참여자용 `/demo`는 [PLAN](../../PLAN.md)에 따라 **가입 없이** 첫 설문 → 체험 → 후기 순서로 진행한다. 데모에는 가입 화면이 없다. 14세 미만 가입 UI를 어느 화면에 둘지 결정하지 않은 채 이 흐름에 넣으면 기존 참가자 과업이 달라진다.
- 보호자 동의 UI를 실제 생년월일·연락처 입력으로 만들면 포트폴리오 시안인데도 개인정보를 수집하는 것처럼 보일 수 있다. 샘플 상태 전환과 화면 전용 안내로 표현하는 방식이 가능하지만, 입력·완료 표현 수준은 사용자 선택이 필요하다.
- PRD의 오래된 “최종 휴대폰·카카오·구글”과 E24의 카카오 첫 인증은 당시 계획 기록이다. 지금의 포트폴리오 구현 범위에는 카카오·네이버가 없다. 휴대폰·구글 인증도 이번 답변으로 새로 승인된 것이 아니다.

## 제안과 남은 선택

1. **권장 배치:** 기존 참가자용 `/demo`와 별도인 포트폴리오 화면에서 가입·보호자 동의 시안을 보여준다. 기존 설문·체험 과업에는 가입 단계를 추가하지 않는다.
2. **권장 표현:** 실제 생년월일·보호자 연락처를 받지 않고 “14세 미만인 경우” 샘플 전환으로 보호자 동의 안내와 화면상의 다음 단계를 보여준다. 화면에 ‘포트폴리오 시안·실제 가입 불가’를 명확히 둔다.

사용자가 선택할 수 있도록 [지속되는 HTML 질문 화면](2026-09-28_E25_가입화면_UI_역질문.html)을 준비했다. 답을 받기 전에는 가입 UI 위치와 입력·완료 단계를 임의로 구현하지 않는다. 이번 E25의 코드·DB·원격 설정·운영 배포 변경은 없다.
