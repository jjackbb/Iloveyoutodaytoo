# E24. 카카오 첫 인증 선택과 가입 대기

> **후속 E25:** 사용자가 포트폴리오 범위로 좁혀 카카오·네이버 로그인/회원가입을 철회했다. 이 파일의 카카오 구현 경로는 과거 검토 기록이다. [최신 결정](2026-09-28_E25_포트폴리오_가입화면범위_재결정.md)을 따른다.

- **작업 위치:** `.claude/worktrees/db-video-local`의 `worktree-db-video-local` 브랜치. 원본 `main`의 별도 변경은 건드리지 않았다.
- **사용자 직접 선택:** 아이디 가입을 대체할 첫 방식은 **카카오 로그인·가입**. 실제 운영자명, 개인정보 보호책임자명, 공개 문의 이메일, 개인정보 처리방침 시행일은 **아직 미정**이며 **가입 대기 유지**.
- **현재 운영 상태:** Supabase `wdzzianhfnupmfbjqqac`의 신규 가입 차단과 카카오 제공자 비활성, 앱의 `/signup` 준비 중 안내를 유지했다. 이 작업에서 인증 코드·DB·제공자 설정·운영 배포를 바꾸지 않았다.

## 코드와 공식 문서 대조

1. 현행 `handle_new_user`는 Auth 사용자를 만들 때 `birth_date` 메타데이터를 요구한다. 생년월일이 없으면 Auth 가입 거래가 실패한다. `user_private.birth_date`도 `NOT NULL`이다. 카카오 OAuth의 첫 로그인에서는 이 앱의 생년월일 메타데이터를 자동으로 받을 수 없으므로 제공자만 켜서는 신규 가입이 작동하지 않는다.
2. `public.auth_provider`에는 `kakao`가 이미 있다. 가입 완료 후 프로필·나이 확인을 분리하려면 Auth 신원만 생긴 임시 단계가 필요할 수 있다. 현재 저장소 권한을 그대로 쓰면 이 단계에서 `avatars`에 본인 경로 파일을 올릴 수 있으므로, 임시 신원을 허용할 경우 Storage를 포함한 모든 앱 쓰기 권한을 가입 완료와 묶어야 한다. 중단된 가입의 Auth 신원 정리도 필요하다.
3. [Supabase 카카오 안내](https://supabase.com/docs/guides/auth/social-login/auth-kakao)는 카카오 개발자 앱, REST API 키, Client Secret, 카카오 로그인 설정, Supabase 제공자 설정을 요구한다. 카카오에 등록할 Supabase 콜백 주소는 `https://wdzzianhfnupmfbjqqac.supabase.co/auth/v1/callback`이다. 앱의 별도 리디렉션 주소도 Supabase 허용 목록에 등록해야 한다. 이 저장소의 현행 앱에는 카카오 콜백 경로와 개발자 앱 자격 정보가 없다. 비밀키는 문서나 채팅에 넣지 않는다.
4. [Supabase 신규 가입 설정](https://supabase.com/docs/guides/auth/general-configuration)은 전체 가입을 끄면 기존 사용자만 로그인할 수 있다고 설명한다. 현재 `disable_signup=true`는 사용자 선택대로 유지한다. [가입 전 훅](https://supabase.com/docs/guides/auth/auth-hooks/before-user-created-hook)은 Auth 사용자 생성을 거절할 수 있지만, 제공자 신원만으로 이 앱에 필요한 실제 생년월일과 보호자 확인을 대신하지 않는다.

## 충돌과 검토할 구현 경로

- PRD의 오래된 `AUTH-01`·§6⑤·⑥에는 **14세 미만 보호자 동의 후 가입**이 적혀 있다. 2026-09-26 이후 PLAN·초기 DB는 **보호자 확인 기능이 완성될 때까지 14세 미만 가입 차단**으로 바뀌었다. 과거 문장을 소급 삭제하지 않고, 이번 설계의 기준을 사용자에게 확인한다.
- **권장 검토안:** 카카오 인증 전 생년월일·필수 동의를 안내하고, 카카오가 돌아온 뒤 서버에서 생년월일과 만 14세 이상 조건을 확인해 앱 프로필을 완성한다. 임시 Auth 신원을 허용한다면 앱 데이터·Storage 접근 차단, 중단/미성년 임시 신원 자동 삭제, 직접 OAuth 주소를 통한 우회 차단을 함께 구현하고 검증한다. 이 구조는 **카카오 인증 순간 Auth 신원이 먼저 생성될 수 있다**는 한계가 있으므로 사용자의 정책 선택 없이 적용하지 않는다.
- **대안:** 임시 Auth 신원도 허용하지 않으려면 카카오 OIDC 토큰을 앱에서 먼저 받아 나이·동의를 확인한 다음 Supabase 신원을 연결하는 별도 인증 경로를 설계해야 한다. 표준 `signInWithOAuth`만으로 끝나지 않으며, 카카오 개발자 설정과 보안 검증 범위가 커진다. [Supabase 카카오 OIDC 안내](https://supabase.com/docs/guides/auth/social-login/auth-kakao)의 `signInWithIdToken` 예시가 검토 시작점이다.

## 다음 실행 조건

결정 질문 3개는 [계속 열어둘 수 있는 HTML 선택 화면](2026-09-28_E24_카카오_인증_역질문.html)에 모았다. 선택 결과는 서버로 전송하지 않고 사용자가 복사해 전달한다.

1. 14세 미만 처리와 임시 Auth 신원 허용 범위를 결정한다. 기존 보호자 인증을 실제로 구현하기 전에는 미성년자 가입 완료를 열지 않는다.
2. 카카오 개발자 앱의 소유·설정 상태를 확인한다. 자격 정보는 카카오/Supabase 관리 화면에만 입력하고, 여기에는 설정 여부만 남긴다.
3. 법적 초안의 운영자·보호책임자·문의·시행일, 보존·국외 처리 항목을 실제 값으로 채우고 사람이 전체 검토한다. 그전에는 `disable_signup=true`와 앱 가입 대기 화면을 유지한다.
4. 인증 경로를 구현한 뒤에는 Auth 계정 생성, 프로필 완료 전 접근, 14세 미만/중단 정리, 카카오 재로그인, 기존 계정 연결, 탈퇴, 개인정보 문구를 별도 확인한다. 이번 E24는 **설계·상태 정리만 완료**했다.
