# E20. 첫 설문·데모·후기 통합과 운영 연결 확인

- **위치:** `.claude/worktrees/db-video-local`, `worktree-db-video-local` 브랜치. 원본 `main`은 건드리지 않았다.
- **사용자 최신 선택:** 첫 설문은 실제 Google Form 사본을 기다리지 않고 [18번 공동 작성 구글폼 프롬프트](../18_공동작성_인터뷰안_기반_구글폼_프롬프트.md)와 [09번 현장 인터뷰 흐름](../09_사전인터뷰_전체흐름_공동작성.md)을 기준으로 한다. 삭제된 원 댓글의 답글은 현재처럼 단독 표시하고 삭제 안내를 유지한다.
- **대상:** 20~30대 3~5명과 직접 인터뷰하는 50대 1명을 한 참여 흐름으로 센다. 첫 설문 → 데모 체험 → 후기 설문 → 두 설문 답변 합쳐 복사·직접 전달. 실제 참여·답변은 아직 없다.

## 구현과 공개 상태

`/demo/pre-survey`에 참여 및 내부 기획용 비식별 요약 동의, 별도 포트폴리오 요약 동의, 평소 표현, 최근 실제 표현·미표현·장면 없음 분기, 공통 반대 사례와 빠진 경험을 넣었다. 서술형은 건너뛸 수 있다. 사용자 출발점 소개는 모든 경험 답변 뒤에만 나온다. 진행자가 참여자의 답을 듣고 대신 입력하는 선택지도 있다.

첫 설문은 서버나 데모 저장소 대신 같은 탭의 `sessionStorage`에 24시간 임시 보관한다. 후기 페이지는 첫 설문이 없으면 시작 링크를 보여주고, 있으면 기존 후기 7문항의 답변과 합쳐 복사한다. 자동 전송은 없다. 복사 실패 시 직접 복사할 칸을 보여준다. 참가자가 실제로 전달해야 수신한 답변이다.

- **코드 커밋:** `306dd53 [DEMO] 첫 설문·체험·후기 답변을 한 흐름으로 연결`.
- **데모 배포:** 추적된 `frontend` 파일만 별도 폴더로 옮기고 Vercel 연결 중 생성된 `.env.local`을 삭제한 뒤, 기존 `oneuldo-demo` 프로젝트에 배포했다. 배포 ID `dpl_Hk5YF19yfdmgVz4ULkqD4ddg2cHs`, READY, 주소 https://oneuldo-demo.vercel.app/demo/pre-survey .
- **확인:** Vercel Turbopack 운영 빌드·TypeScript·새 경로 생성 PASS. 로컬·공개 격리 Chrome에서 첫 설문 누락 안내, 동의 거절 시 임시 저장 없음, 두 갈래 분기, 출발점 소개 시점, 데모 이동, 두 답변 합쳐 클립보드 복사, 진행자 입력을 확인했다. 실기기·실제 참가자·응답 전달은 `NOT_RUN`.

## 운영 앱 경계

이전의 "원격 DB 당분간 보류" 결정 때문에 E19는 앱 코드와 SQL만 브랜치에 두도록 추천했다. 사용자는 이 추천 이유를 물었다. 이전 보류를 이번 앱 이식 요청에 기계적으로 적용한 판단이었고, 최신 의도를 다시 확인해야 한다. 운영 적용을 원한다면 기존 보류 결정을 갱신해 기록한다.

이번 세션에서 읽기 전용으로 확인한 것은 다음과 같다.

1. Vercel 계정에서 데모 `oneuldo-demo`와 기존 앱 `iloveyoutodaytoo` 프로젝트를 확인했다. 기존 앱 프로젝트 루트는 `frontend`다. 기존 앱에는 배포하지 않았다.
2. 로컬 Supabase CLI는 인증돼 있지만 `projects list` 결과가 **다른 서비스 `yumidang` 한 개**다. 오늘도 사랑해 대상 ref `wdzzianhfnupmfbjqqac`는 이 계정에 나타나지 않는다. 이번 시점의 원격 스키마·Auth·RLS는 확인할 수 없었다. 다른 프로젝트의 MCP·CLI를 대상 DB로 사용하지 않았다.
3. 앱 로컬 코드와 SQL은 앞선 `1f58a84`에 있다. 대상 DB의 초기 마이그레이션 두 개와 새 `20260928000001_memory_expression.sql` 적용 순서를 확인해야 하며, 새 SQL 실행·원격 RLS·앱 브라우저 동작·기존 앱 배포는 여전히 `NOT_RUN`이다. 실제 가입 전 개인정보 처리방침 전체는 사람이 검토해야 한다.

## 다음 작업

- 사용자에게 운영 DB와 기존 앱 배포까지 이번 요청에 포함되는지 최종 선택을 받는다. 적용을 선택하면 대상 Supabase 프로젝트가 보이도록 이 환경의 연결을 바꾼 뒤, E3 절차의 대상·빈 DB 여부·Auth 설정·마이그레이션 목록을 읽기 전용으로 다시 확인한다.
- 대상 확인과 권한·RLS 검사가 끝나면 DB 변경문을 순서대로 적용하고 기존 앱 배포 및 실제 흐름을 확인한다. 현재 연결 상태에서 바로 적용하거나 기존 앱만 먼저 배포하지 않는다.
- 참여자에게는 [최신 안내 문안](../25_데모내_후기설문_복사전달_진행안.md)을 사용한다. 실제 응답·실기기 검증은 관찰 뒤 기록한다.
