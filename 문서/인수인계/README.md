# Claude 작업 인수인계 규칙과 양식

큰 작업 하나가 끝나거나 사용자 판단을 기다리게 되면 `YYYY-MM-DD_작업명.md`를 **새 파일**로 남긴다. 가장 최근 파일을 읽고 시작하고, 과거 파일은 결과와 결정의 이력으로 보존한다. 인터뷰안 담당 세션의 문안과 [기존 병행 인수인계](../06_병행세션_인수인계.md)의 상대 섹션을 덮어쓰지 않는다.

아래 양식을 복사해 사실로 확인한 것만 채운다. 실행하지 않은 검사에 `PASS`를 적지 않는다. 비밀 키·참여자 실명·사적인 내용은 넣지 않는다.

```md
# YYYY-MM-DD 작업명 — 다음 세션 인수인계

- 기준 시각·담당 범위:
- 읽은 기준 문서와 최신 사용자 선택:
- 시작 당시 작업 트리와 다른 세션의 담당 파일:

## 이번에 완료한 일

- 변경 파일·핵심 이유:
- 사용자 결정 / AI 구현 판단 / 실제 관찰을 구분한 기록:

## 검증과 남은 위험

| 검사·환경 | 결과(PASS/FAIL/NOT_RUN/BLOCKED) | 근거와 한계 |
|---|---|---|
| 로컬 정적 검사 |  |  |
| 로컬 DB·RLS |  |  |
| 브라우저·실기기 |  |  |
| 원격 DB·배포·실사용자 |  |  |

## 다음 세션의 첫 작업

1. 먼저 읽을 파일·확인할 명령:
2. 첫 미완료 작업과 완료 조건:
3. 손대지 말아야 할 파일·대기 중인 다른 세션 작업:

## 사용자에게 한꺼번에 확인할 선택

- 없다면 `없음`. 있다면 이유·선택지·추천·영향을 묶어서 적는다.
```

인수인계 작성 뒤 [연속 실행 지시서](../12_클로드_연속실행_지시서.md)의 해당 단계와 [PLAN](../../PLAN.md)의 상태를 대조한다. 이전 인수인계의 `PASS`는 새 코드의 검사 결과가 아니다.
