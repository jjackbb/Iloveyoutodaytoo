### DB 개념을 가족방 한 개로 — 백엔드 입문용 짧은 설명

엄마(A)가 "우리집" 방을 만들고 딸(B)을 초대한 상황.

- **표 = 무엇을 저장하는가:** `rooms`에 "우리집" 한 줄, `room_members`에 엄마·딸 한 줄씩, `memories`에 추억 한 줄, `memory_photos`에 그 추억의 사진 줄들. `users`는 방 사람에게 보여도 되는 이름·프로필 사진, `user_private`는 엄마만 볼 생년월일·아이디.
- **외래 키 = 어떤 기록을 잇는가:** 추억의 `room_id`가 "우리집"을 가리키고, 사진 줄의 `memory_id`가 그 추억을 가리킨다. 추억을 지우면 사진 줄·댓글·반응·알림이 따라 지워진다(`on delete cascade`).
- **RLS = 누가 읽고 쓰는가:** 추억 한 줄마다 DB가 "지금 읽는 사람이 이 방의 활성 참여자인가, 이 추억이 방 공유(room)인가 작성자만(private)인가"를 검사한다. 엄마가 혼자일 때 쓴 추억은 `private`라 딸이 나중에 들어와도 못 본다.
- **Storage = 파일 자체를 어디에 두는가:** 사진·영상·목소리 파일은 DB가 아니라 `media`·`video`·`voice` 버킷에 있고, DB에는 경로만 있다. 이제 버킷은 "경로가 우리집 폴더인가"가 아니라 **"내가 읽을 수 있는 추억에 연결된 파일인가"**로 읽기·서명을 허락한다.

### 사용자 결정 / AI 구현 판단 / 실제 관찰 구분

**사용자 결정(지시서·첫 인수인계 그대로 구현):** 과거 데이터 복구 불필요 · 기존 앱의 성인 가입→방·초대→추억·댓글·사서함 복구 · 추억에 영상 1개(파일 선택+앱 안 촬영, 다른 수단과 함께, 영상만으로도 가능) · 영상 0~30초, 50MB 초과는 이유 안내 후 재선택, 자동 압축 없음 · 음성 0~60초(추억·댓글·사서함) · 저장 순간 활성 참여자 1명이면 작성자만, 2명 이상이면 방 공유, 이후 불변 · 작성자 삭제 = 연결 파일·댓글까지 완전 삭제 · 관계 유형·답장 잠금 제거, 자유 호칭 유지 · 사서함 영상 작성 없음 · 실제 보호자 확인 전 미성년 가입 차단 · 자기 추억 반응 허용 · 격리 로컬 DB(Docker 호환 실행기+Supabase CLI)로 검사.

**AI 구현 판단(사용자가 정하지 않음 — 되돌릴 수 있다, 원격 미적용):**
1. 실행기는 Colima(Homebrew)로, Supabase CLI는 Homebrew 설치가 Xcode 도구 버전 문제로 실패해 npm 패키지(`~/.local/supabase-cli`, 2.118.0)로 설치했다.
2. 공개 범위는 `memories.visibility` 열(`private`/`room`)을 저장 트리거가 채우고, 방 행 잠금(`for update`)으로 초대 수락·나가기·저장을 직렬화했다. 입력값이나 이후 수정은 무시한다.
3. 개인 정보는 `users`(이름·프로필 사진)와 `user_private`(아이디·이메일·생년월일·보호자·큰 글자)로 나눴다. 열 권한으로 앱은 이름·사진·큰 글자만 고칠 수 있다.
4. 파일을 기록에 붙일 때 **그 파일을 올린 사람이 지금 저장하는 사람인지** DB가 확인한다. 남의 비공개 파일 경로를 자기 공유 추억에 붙여 새게 하는 우회를 막기 위해서다.
5. 추억 삭제는 행을 먼저 지우고(그 순간 모두의 접근 차단) 파일 목록을 `storage_deletion_jobs`에 남긴 뒤 Storage에서 지운다. 실패하면 "추억은 지웠지만 파일 정리를 마치지 못했어요. [삭제하기]를 한 번 더 눌러 주세요"를 보여주고, 다음 삭제·고치기 때도 다시 시도한다. Storage 삭제가 내부적으로 읽기 권한을 요구해서, **요청자가 "지우는 중"으로 표시한 30초 동안만** 그 파일 읽기를 요청자에게 연다.
6. 탈퇴하면 "작성자만 읽는 추억"은 아무도 못 읽게 되므로 함께 지우도록 했다(방 공유 추억은 예전처럼 "탈퇴한 사용자"로 남는다). **사용자 데이터 삭제 규칙이라 아래 질문 3에서 확인이 필요하다.**
7. 미성년 가입 화면에서 보호자 이름·연락처·동의 체크 칸을 없애고 "준비 중이라 아직 가입할 수 없어요"만 보여준다. DB도 생년월일로 한 번 더 막는다. `guardian_verifications` 표·확인 함수·24시간 정리 예약 작업은 구조만 남겼다.
8. 사서함 `message_type` 열거형의 `video` 값은 옛 표시 코드 때문에 남기고, 제약으로 새 영상 메시지 작성을 막았다. `send_mode`는 text+CHECK 대신 열거형으로 바꿨다(앱 타입과 일치).
9. 쓰이지 않는 연속 기록(`daily_streaks`)과 방 테마(`rooms.theme`)는 PRD 기능일 수 있어 지우지 않고 그대로 옮겼다. 쓰이지 않던 `memories.media_url`·`media_type`·`deleted_at`, `room_members.has_replied_first_invite`, `heart_messages.replied_at`은 뺐다.
10. 영상 칸의 겉모습은 기존 목소리·손글씨 칸과 같은 부품으로만 만들었다. `frontend/CLAUDE.md`의 디자인 관문 스킬(`frontend-design-direction`·`design`)이 이 세션에 없어 **밟지 못했다.** 시각 설계 확정이 아니다.
