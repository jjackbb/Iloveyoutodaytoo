## 사용자 요청과 작업 경계

사용자가 작업 범위를 `PLAN.md`의 남은 작업 전체로 넓혔다. 확인 필요·애매·충돌 사항은 임의 처리하지 말고 마지막에 한꺼번에 역질문하며, 5개 이상이면 추천안·다른 선택지·기타 직접 입력이 있는 HTML 화면으로 띄우라고 했다. 실제 조사·테스트·원격 DB 적용은 이 요청만으로 완료되거나 승인된 것으로 보지 않는다. 기존 원격 DB 보류 결정은 유지한다.

- [실행판](../19_PLAN_남은작업_실행판.md): 0~7단계별 완료·미실시·다음 조건, 세 해결 대안과 반례, 현재 데모 흐름, 검증 경계, 포트폴리오에 쓸 수 있는 문장과 아직 쓸 수 없는 문장을 정리했다.
- [사용성 설문 초안](../20_사용성테스트_설문_초안.md): 문제 확인 설문과 구분되는 사용 후 자기 보고 7문항을 제안했다. 실제 폼은 만들거나 발송하지 않았다. [관찰 양식](../07_사용자테스트_과업과_관찰기록_틀.md)에 설문·화면 관찰·참여 중복 구분 칸을 보탰다.

## 검증과 한계

- 문서 링크 확인: PLAN·README·07·18~22의 로컬 상대 경로 누락 없음. HTML에 질문 6개·추천 6개·기타 6개가 있고 내장 JavaScript `node --check` 통과. `git diff --check` 통과. 공개 데모 `/demo`는 읽기 전용 HTTP 요청에서 200 응답(2026-09-28 03:59 KST).
- 데모 코드·원격 DB·기존 Vercel 프로젝트는 이 단위에서 바꾸지 않았다. E6 당시 배포본 자동 검사 37/37은 과거 근거다. 이번에 실제 기기·참가자·폼 설정·참가자 응답을 확인하지 않았다. 문제 가설·기능 효과·개선 효과는 아직 주장할 수 없다.
- 원본 `main`에는 별도 미커밋 변경이 있어 합치지 않았다. 이 작업은 `worktree-db-video-local`에서 계속한다.
