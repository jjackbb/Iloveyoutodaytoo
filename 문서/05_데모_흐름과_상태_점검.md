기준일: 2026-09-25. 사용자가 인터뷰와 병행할 첫 작업으로 **화면 흐름·상태 설계 점검**을 선택했다. [PLAN](../PLAN.md)의 체험 범위와 [기존 화면 목록](03_데모_현재흐름과_상태목록.md)을 코드와 대조했다. 아래의 '현재'는 코드에서 읽힌 경로·분기이며 브라우저·실기기에서 재현한 결과가 아니다. 이후 음성 녹음 최소 시간 조건의 코드·문서 정정만 이 표에 반영했고, 변경 범위와 검사는 [최신 변경 점검](10_최신변경_잔여점검.md)에 구분했다. 인터뷰 전 해결 방향·새 기능·시안은 확정하지 않는다.

| 저장소 불가·초기화 | 저장소를 열지 못하면 예시를 읽기 전용으로 보여주며, 저장·반응을 막는다. 초기화는 확인창 뒤 데모 데이터와 초안을 예시 상태로 되돌린다. 작성 중에는 초기화 버튼을 잠근다. | 읽기 전용 안내와 복구 경로, 초기화 범위 이해를 브라우저에서 확인한다. 가족방의 빈 목록 분기는 코드에 있지만 기본 예시를 지우는 일반 화면이 없어 현재 UI에서 도달 가능한지는 확인이 필요하다. |

## 사용자 선택과 남은 설계 지점

1. **작성 화면 상단의 뒤로 가기 — 사용자 선택:** 작성에 들어온 화면으로 돌아간다. 홈에서 왔다면 홈, 가족방에서 왔다면 가족방이다. 작성 주소로 직접 들어와 이전 데모 화면이 없다면 가족방으로 돌아간다. 현재 코드는 항상 가족방으로 가므로 후속 구현 때 진입 경로에 따른 복귀가 필요하다.
2. **녹음 중 이탈 — 사용자 선택:** 상단 뒤로 가기, 도구막대의 데모 링크, 브라우저 뒤로 가기에서는 먼저 이탈을 확인한다. 계속 작성하겠다면 현재 화면·녹음을 유지하고, 나가겠다면 진행 중인 녹음을 버린 뒤 해당 경로로 간다. 현재 코드에는 이탈 확인이 없다. 확인 방식·문구와 브라우저별 실제 동작은 후속 설계·실기기 검증 대상이다. 탭 닫기·새로고침의 브라우저 기본 경고와 동일하게 동작한다고 가정하지 않는다.

| 저장소를 못 여는 경우 | 예시를 읽기 전용으로 보여주고 “초기화로 다시 시도”를 안내한다. 그러나 초기화도 같은 저장소를 열어야 하므로 저장소 접근 자체가 막힌 경우에는 이 안내로 복구할 수 없다. 손상된 저장 기록을 초기화하는 경우와 구분해야 한다. | 원인별 복구 안내를 고친 뒤 저장소 접근 불가·기록 손상 상태를 각각 확인한다. 현재는 코드에서 발견한 안내 불일치이며 실제 발생 빈도는 모른다. |

### 후속 작업의 순서와 확인 질문

1. **이미 정해진 목표 동작:** 작성 상단 복귀 경로와 녹음 중 세 이탈 경로의 확인·버리기는 앞의 사용자 선택대로 후속 구현 항목에 둔다. 새 선택으로 되묻지 않는다.
2. **코드에서 확인한 안내 불일치:** 저장소를 열지 못할 때의 초기화 안내와 알 수 없는 주소의 안내를 후속 화면·오류 정리 항목에 둔다. 실제 복구 성공 여부는 브라우저에서 확인한다.
3. **본인 기록 반응 — 사용자 선택:** “혼자서 일기처럼 사용할 수 있잖아. 현재처럼 둬.” 본인이 남긴 기록에도 ‘마음 전하기’를 허용한다. Codex는 상대의 반응을 구분하기 위해 숨기는 안을 권했지만 사용자는 혼자 쓰는 경우를 이유로 현재 동작 유지를 선택했다. 이는 본인 반응에 관한 선택이며 단독 사용 시나리오 전체의 설계·검증 완료를 뜻하지 않는다.
4. **실행 검증 `NOT_RUN`:** 비로그인 진입, 작성 왕복·새로고침, 녹음 중 각 이탈, 마이크 거부, 사진 오류, 저장 실패·재시도, 상대 역할의 읽음·반응, 초기화·잘못된 주소, 모바일·실기기 동작. 이 점검은 코드 수정·브라우저 재현·실제 사용자 테스트를 포함하지 않는다.

인터뷰 결과에 따라 해결 방향이 바뀔 수 있으므로 다른 새 화면·기능은 여기서 확정하지 않는다.
