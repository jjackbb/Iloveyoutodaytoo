# 대표 화면 비교 준비 — 근거·변수·검토표

기준일: 2026-09-25. 사용자의 “다음 작업 ㄱㄱ”를 [남은 병행 후보](04_인터뷰와_병행할_준비작업.md) 중 **대표 화면 비교 준비**로 해석해 작성했다. [PLAN 3단계](../PLAN.md)의 홈·작성·상세 두 시안을 나중에 눈으로 비교할 때 쓸 자료다. 처음 작성한 화면 설명은 코드와 문서 읽기 근거였고, 이후 사용자의 요청으로 현재 데모와 보관된 카드 시안을 Safari 창에 열었다. 아직 두 시안을 제작하거나 선택하지 않았다.

## 재사용할 자산과 현재 기준

| 자료 | 위치와 확인한 내용 | 비교 시 취급 |
|---|---|---|
| 로고·마크 | [로고](../frontend/public/brand/logo.svg), [마크](../frontend/public/brand/mark.svg), [디자인 기준](../design.md) 1절 | 기존 브랜드를 사용한다. 새 로고를 비교 변수로 섞지 않는다. |
| 색·글자 | [디자인 기준](../design.md) 2~3절: 중립 바탕·흰 카드·번트 강조색 `#BF3F0D`, Pretendard. [데모 검토](../design/DEMO_REVIEW.md)는 같은 색·글자 계열을 쓴다. | 배경을 강조색으로 채우거나 새 서체를 도입하는 비교는 이번 범위가 아니다. 가독성·대비는 시안에서 확인한다. |
| 앨범 카드 | [결정 기록](../design/DECISIONS.md)과 [보관된 확정 시안](../archive/design/canvas/components/Main.dc.html): 4:3 사진, 16px 모서리, 좌하단 이름표, 새 마음 **숫자 배지** | 이 결정은 고정한다. `design.md`의 일반 카드 22px이나 결정 기록의 과거 점 표시 문장을 이번 앨범 카드의 최신 기준으로 읽지 않는다. 숫자의 부담감은 실제 관찰 대상이다. |
| 데모 흐름·정책 | [PLAN](../PLAN.md) 3~4절, [화면·상태 목록](03_데모_현재흐름과_상태목록.md), [흐름 점검](05_데모_흐름과_상태_점검.md) | 세 수단 중 먼저 선택한 뒤 작은 탭으로 전환, 브라우저 내부 저장과 가상 인물 표시, 본인 기록 반응 허용을 유지한다. 합의한 뒤로 가기·녹음 중 이탈은 목표 동작이며 현재 구현과 구분한다. |

**이름표 규격 재적용:** 처음 자료를 정리할 때 [확정 카드 규격](../design/DECISIONS.md)의 **29px·좌우 9px**과 [데모 CSS](../frontend/src/app/demo/demo.css)의 **32px·12px** 차이를 발견했다. 사용자는 이를 바꾸기로 한 후속 결정이 없었다고 확인하고 다시 적용하자고 했다. 데모 CSS를 **29px·좌우 9px**로 수정했다. 코드와 HTTP 응답은 확인했으나, 사용자의 시각적 판단과 브라우저 조작 검증은 아직 남았다.

**눈으로 볼 현재 자료:** Safari에 현재 [홈](http://127.0.0.1:4317/demo), [작성](http://127.0.0.1:4317/demo/rooms/family/compose), [상세 예시](http://127.0.0.1:4317/demo/rooms/family/memories/example-heart), [보관된 카드 시안](../archive/design/canvas/components/Main.dc.html)을 열었다. 로컬 서버가 실행 중일 때만 앞의 세 주소가 열린다. 세 데모 주소는 HTTP 200을 확인했고, 개발용 HMR 경로가 Supabase 키 없이 500을 내던 문제는 `proxy.ts`의 matcher에서 해당 경로를 제외한 뒤 같은 요청이 404로 바뀐 것까지 확인했다. 이 응답 확인은 화면 렌더링·클릭 동작·마이크·화면 녹화 검증을 뜻하지 않는다. VS Code 권한은 사용자 설명에 따라 재시작 후 확인한다.

## 홈·작성·상세의 코드상 현재 모습

| 대표 화면 | 현재 코드에서 읽힌 구성 | 두 시안에서 확인할 질문 |
|---|---|---|
| 홈 [`/demo`](../frontend/src/app/demo/demo-app.tsx) | 인사·제목 → 4:3 가족방 카드와 새 마음 숫자 → 짧은 작성 안내 → ‘마음 남기기’ 버튼. 가족방 카드와 작성 버튼이 각각 다른 행동으로 열린다. | 첫눈에 **가족방 열기**와 **마음 남기기**를 구별하는가? 숫자 배지가 의미를 전달하면서 부담으로 읽히지 않는가? |
| 작성 [`/demo/rooms/family/compose`](../frontend/src/app/demo/demo-app.tsx) | 손글씨·목소리·사진 3개 선택 버튼이 먼저 보이고, 선택 뒤 작은 탭이 된다. 입력 영역 아래 선택형 한마디와 하단 저장 버튼이 있다. 매체 하나 이상이 있어야 저장된다. | 첫 수단을 쉽게 고르는가? 선택 뒤 입력 공간과 다른 수단 탭을 함께 찾는가? 저장 가능 상태·오류·입력 보존이 분명한가? |
| 상세 [`/demo/rooms/family/memories/{id}`](../frontend/src/app/demo/demo-app.tsx) | 작성자와 예시 표시 → 담긴 손글씨·사진·목소리·한마디 → ‘마음 전하기’ 반응 → 안내와 가족방 복귀 버튼. 작성자 본인도 반응할 수 있다. | 남긴 내용을 먼저 읽거나 재생하는가? 반응의 뜻과 실제 전송되지 않는 체험 범위를 이해하는가? 가족방으로 돌아가 기록을 다시 찾는가? |

[소개 화면](../frontend/src/app/welcome/page.tsx)은 현재 목소리·사서함 중심 문구를 쓴다. 사용자는 가족방과 세 수단을 포괄하는 설명 방향을 선택했지만, 실제 한 문장과 배치는 [데모 검토](../design/DEMO_REVIEW.md)에 **미확정**으로 남아 있다. 대표 화면의 첫인상과 함께 확인하되 기존 문구를 승인된 카피로 사용하지 않는다.

## 두 안을 만들 때 비교할 요소

동일한 데모 자료·화면 크기·주요 문장을 두 안에 사용하고, 아래의 **배치와 정보 밀도**를 바꿔 본다. 이는 시안 제작을 위한 비교 축이며 A/B 화면의 실제 배치나 선호를 미리 정한 것이 아니다.

| 화면 | 비교할 변수 | 유지할 행동·내용 | 사용자에게 보여줄 때 볼 것 |
|---|---|---|---|
| 홈 | 가족방 카드·작성 버튼의 시선 순서, 첫 화면에 보이는 안내량, 새 마음 숫자 주변의 여백 | 카드 4:3·16px, 이름표 29px·좌우 9px, 숫자 배지, 가족방 열기와 작성의 두 경로 | 어느 행동을 먼저 예상하는지, 숫자를 어떻게 해석하는지, 첫 화면이 답답하거나 비는지 |
| 작성 | 3개 수단 선택의 크기·간격, 선택 뒤 탭과 입력 공간의 비율, 하단 저장 행동의 표시 | 첫 선택 → 작은 전환 탭, 세 수단 추가 가능, 입력 유지·저장 조건 | 조작법 설명 없이 첫 수단을 찾는지, 탭 전환과 저장 상태를 알아보는지 |
| 상세 | 기록 매체와 반응의 시각적 위계, 긴 기록일 때 간격, 가족방 복귀 버튼의 자리 | 저장한 모든 매체·작성자·예시 표시, 본인 반응 허용, 가족방 복귀 | 내용을 확인하고 반응·다시 보기 경로를 이해하는지 |

**함께 비교할 상태:** 새 마음 0개/여러 개, 작성 전/수단 선택 후/매체 추가 후, 짧은 기록/긴 기록, 저장 실패, 마이크 거부, 없는 상세 주소. 두 안에 같은 조건을 적용해 화면 차이와 데이터 차이를 혼동하지 않는다. 모바일 폭·글자 확대·키보드 조작·터치 영역·명도 대비는 [PLAN 기준](../PLAN.md)에 맞춰 확인한다. 실제 검사 결과는 시안 제작·기술 확인 단계에서 별도로 기록한다.

## 사용자 검토 기록 칸 — 시안 제작 뒤 사용

| 화면 | 안 A에서 먼저 보인 행동·읽힌 의미 | 안 B에서 먼저 보인 행동·읽힌 의미 | 사용자 선택·수정 요청·이유 | 미확인·다음 확인 |
|---|---|---|---|---|
| 홈 | 미제작 | 미제작 | 미선택 | 사전 인터뷰 결과와 실제 화면 확인 대기 |
| 작성 | 미제작 | 미제작 | 미선택 | 사전 인터뷰 결과와 실제 화면 확인 대기 |
| 상세 | 미제작 | 미제작 | 미선택 | 사전 인터뷰 결과와 실제 화면 확인 대기 |

사전 인터뷰에서 실제 어려움을 확인한 뒤, 두 안의 목적·바뀐 요소·사용한 데모 버전을 적고 **실제 화면을 나란히 보여준다.** 사용자 선택이 생기면 선택 이유와 반대 의견을 함께 기록한다. 그 뒤에 선택한 기준을 전체 흐름에 적용하고 브라우저·실기기에서 다시 확인한다. 기존 자료의 타인 화면 참고나 오래된 캡처는 현재 데모의 동작 증거로 쓰지 않는다.

**현재 상태:** 비교 기준 정리, 현재 데모·보관 시안 Safari 탭 열기, 이름표 규격 CSS 재적용, 세 주소 HTTP 200 확인까지 수행했다. 두 시안·현재 화면 캡처·사용자 시안 선택·선택안의 전체 흐름 적용·브라우저 상호작용/실기기 검사·실제 참여자 관찰은 `NOT_RUN` 또는 미완료다. VS Code를 재시작하면 로컬 서버가 멈출 수 있으므로 주소가 열리지 않을 때는 `frontend`에서 `npm run dev:demo`를 다시 실행해야 한다.
