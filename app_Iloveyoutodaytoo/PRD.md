## 1. 서비스 개요

- **핵심 문제** — 독립·취업으로 자녀와 부모 사이가 물리적·심리적으로 멀어지면서,
  서로에게 안부나 애정을 표현할 **계기(핑계)** 가 사라졌다. 카카오톡 대화는 휘발되고
  깊이 있는 소통으로 이어지지 않는다.
- **제공 가치** — 사진과 짧은 영상 아카이빙을 매개로 대화의 물꼬를 트고,
  **'답장 미션'** 이라는 따뜻한 강제 장치로 표현이 서툰 가족의 교류를 지속시킨다.

## 2. 타깃 사용자

**주 사용자 — 자녀 (2030 직장인)**
따로 살며 바쁘다는 핑계로 부모님께 다정한 말을 건네지 못하는 것에 **부채감**을 느낀다.
**"후회하고 싶지 않다"** 가 이 사람을 움직이는 감정이다.
앱에 능숙하고 인스타·틱톡의 제스처가 몸에 익어 있다.

**동반 사용자 — 부모 (5060), 초대받아 들어온다**
자녀의 일상이 궁금하지만 방해가 될까 봐 먼저 연락하기 조심스럽다.

새 개념은 낯설어도 익숙한 동작은 그대로 한다.

**대상이 아닌 사용자** — 70대 이상 디지털 취약 계층.

## 4. 상세 기능 명세

### [ALBUM-01] 앨범방 생성 ✅

1. 홈에서 '앨범방 만들기' → 2. 이름 입력 → 3. 대표 이미지/기본 테마 선택 →
4. 생성 완료 시 홈에 카드 추가 + 상세 화면 이동. 방 전용 **기본 감정 사서함**이 함께 생긴다.

- **입력** — 필수: 앨범방 이름 / 선택: 대표 이미지, 설명, 기본 테마
- **예외 1** — 이름 미입력 → "앨범방 이름을 입력해주세요."
- **예외 2** — ⏸ **보류.** 원래는 "무료 1개 초과 시 프리미엄 안내"였으나 **구독 모델 자체가 보류**다.
  지금은 개수 제한이 없다.
- **정책** — 로그인 회원만 생성, 생성자가 관리자. 이름 2~20자 권장.
- **🗑폐기** — 관계 유형(가족/연인/친구/나 자신) 선택. 구현이 이미 안 묻고 있었고 문서만 남아 있었다.
- **개정** — 앨범방 이름·커버는 **각자 자기 화면에서만** 바꾼다(카카오톡 단체방 방식).
  방장이 바꿔서 모두의 화면이 바뀌면 "어제 있던 방이 없어진" 것으로 읽힌다.

### [ALBUM-02] 사진 및 짧은 영상 업로드 ✅

1. 방에서 '추억 올리기' → 2. 사진/영상 선택 → 3. 설명 입력 → 4. 업로드 완료 시 피드 등록 + 구성원 알림.

- **입력** — **개정됨(2026-08-25).** 필수는 **목소리 3초 이상** 하나뿐이다.
  사진·영상·날짜·문구·함께한 사람은 전부 **선택**이다 — 그전에는 사진 1장 이상을 함께
  요구했으나, 목소리가 중심인 앱에서 사진을 강제하면 "지금 찍을 사진이 없어서"
  마음을 못 남긴다(§6-⑫).
- **예외 1** — 지원하지 않는 형식 → "지원하지 않는 파일 형식이에요."
- **예외 2** — **개정됨.** 원래 "2~3초 초과 차단"이었으나 **최대 30초**로 바꿨다(§6-③).
  Supabase 무료 플랜의 **파일당 50MB 상한**도 함께 걸리므로 **길이·용량 두 가지를 모두** 검사하고,
  막힐 때는 실제 용량을 숫자로 보여준다.
- **정책** — 해당 방 구성원만 업로드. 미디어는 클라우드(Supabase Storage) 저장.

### [MSG-01] 사진/영상별 마음 메시지 ✅

1. 상세 화면에서 '마음 남기기' → 2. 유형 선택(텍스트/음성/영상) → 3. 작성·녹음 →
4. 저장 시 답글로 노출 + **감정 사서함 자동 적재**.

- **분량** — 텍스트 300자, **음성 60초**, **영상 30초**
- **예외 1** — 빈 메시지 저장 시도 → "내용을 입력해주세요."
- **예외 2** — 녹음·촬영 권한 거부 → 권한 안내 + 텍스트 입력으로 대체
- **정책** — 실시간 채팅이 아니라 **특정 사진/영상을 겨눈 비동기 답글** 구조
- **🗑폐기** — 감정 태그(사랑해·고마워 등). 고르는 부담만 늘고 쓰이지 않았다.

### [INVITE-01] 초대 링크 및 QR 생성 ✅

1. 방 설정에서 '구성원 초대' → 2. 초대 메시지(음성/텍스트/영상) 작성 →
3. 작성 완료 시 고유 초대 링크와 QR 생성.

- **예외 1** — 메시지 없이 링크 생성 시도 → "초대 메시지를 먼저 작성해야 링크를 만들 수 있어요."
- **정책** — QR은 오프라인 모임에서 카메라만 켜서 들어올 수 있게 하는 보조 수단.
  (원문의 "디지털 취약 계층" 표현은 타깃 개정에 따라 삭제)
- **🗑폐기** — 초대 시 관계(엄마·아빠·연인) 선택. ALBUM-01의 관계 유형 폐기와 같은 이유.

### [INVITE-02] 초대 링크로 가입 후 앨범 입장 ✅

1. 링크·QR로 랜딩 접속 → 2. 초대자의 메시지 선재생 → 3. 회원가입 → 4. **바로 입장**.

- **출력** — 답장을 남기면 초대한 사람에게 "답장이 도착했어요" 알림
- **예외 1** — 음성·영상 답장이 곤란하면 텍스트 탭으로 전환
- **정책** — 첫 답장은 **권하되 막지 않는다.** 남긴 답장은 피드·사서함에 함께 보관된다.

> **🗑 '준회원 → 구성원' 관문은 폐기했다** (2026-08-25).
> PRD에는 있었지만 `member_role` 은 처음부터 `admin | member` 뿐이었다 —
> **코드가 옳았고 문서만 남아 어긋나 있었다.** 이제 가입하면 바로 구성원이 된다.
>
> **폐기한 이유.** 초대로 들어온 사람을 문 앞에서 한 번 더 막는 구조인데,
> 그 문을 통과해야 하는 쪽이 **활성화가 일어나야 할 부모(5060)** 다(§2).
> 여기서 막으면 이탈이 가장 크게 난다.
> 답장은 이미 **답장 미션([MISSION-01])** 이 뒤에서 유도하고 있으므로 관문이 이중이었다.

### [BOX-01] 감정 사서함 ✅

메시지가 등록되는 순간 방별 사서함에 자동 적재된다. '받은 마음'·'보낸 마음' 탭,
날짜별·구성원별 정렬.

- **예외 1** — 원본이 삭제된 경우 → "원본 게시물이 삭제된 마음입니다. 메시지는 계속 보관됩니다."
  (실제 구현은 **소프트 삭제**다 — 행을 지우지 않고 `deleted_at` 을 찍어 조회에서 뺀다)
- **정책** — 내가 보냈거나 내가 받은 메시지만 열람. 자동 삭제 없음, 수동 삭제 원칙.
- **개정** — 사서함 **정리 모드**는 "내 화면에서만 치우기"다. 진짜로 지우면 상대의 보낸함에서도
  사라지므로 문구도 "삭제"가 아니라 **"치우기"**.

### [MISSION-01] 답장 미션 및 열람 제한 ✅

발신자별로 **"읽었지만 답장하지 않은 메시지"** 가 5개가 되면, 그 사람의 다음 메시지에 락이 걸린다.
답장을 보내면 풀린다.

- **예외 1** — 미션을 안 끝내고 나가면 락 유지
- **예외 2** — 발신자별로 카운트가 완전히 별개. A의 락이 B에게 영향을 주지 않는다
- **정책** — 앱 전체를 막지 않는다. **오직 '그 발신자의 다음 메시지를 여는 행동'에만** 락을 건다
- **구현 메모** — 락을 컬럼에 저장하지 않고 **셀 때마다 계산**한다(`locked_senders()`).
  저장하면 답장·삭제 때마다 같이 고쳐야 하고, 한 군데만 놓쳐도 "답장했는데 안 풀리는" 상태가 남는다

### [AUTH-01] 가입과 만 14세 미만 보호자 동의 ✅ / 문자 확인 작업 중

- 가입하는 **모든 사람에게 생년월일**을 받는다. 만 14세 미만인지 알아야 하기 때문이다
- 만 14세 미만이면 **보호자 성함·연락처·동의**를 추가로 받아야 가입이 완료된다
  (개인정보보호법 §22조의2)
- **🚨 `users.birth_date` 의 NOT NULL 을 풀지 말 것.** 이 제약은 나이 제한용이 아니라
  **보호자 동의 분기를 태우기 위한 것**이다. 풀면 그 분기가 통째로 죽는다.
  소셜 로그인을 붙일 때도 추가 정보 화면에서 생년월일을 받아 **같은 블록을 재사용**한다
- **작업 중** — 지금은 보호자 번호를 받아 저장만 하고 문자를 보내지 않는다.
  **동의 요청 문자 + 인증번호 확인**을 붙이는 중이다(§6-⑤)

## 6. 최근 방향 조정 (2026-08)

> 이 절이 **"지금 무엇이 왜 바뀌었나"** 를 모아둔 곳이다. 결정의 상세 근거는
> `frontend/_workspace/14_decisions_2026-08-24.md`, 과정 해설은 `15_process_notes.md`.

**① UX 기준선: 시니어 → 카카오톡** (2026-08-20)
"시니어라서 안 된다"로 기능을 깎지 않는다. 부모 세대는 카카오톡을 잘 쓴다.

**② 몽실이 작성 흐름** — 시안 완료, 적용 대기
구름 캐릭터를 **길게 눌러 녹음하고, 위로 던져 올린다.** 프로토타입은
`frontend/_workspace/13_mongsil_prototype.html`. 적용 범위는 **앨범방 작성 화면만**이며,
기존 작성 화면을 남겨 **팀원 회의 후 되돌릴 수 있게** 한다.

**③ 영상 최대 30초** (기존 2~3초)
비트윈처럼 **다운로드 없이 바로 재생되는 짧은 영상**을 목표로 한다.
2~3초는 너무 짧다는 판단. 답장 영상까지 전부 적용.
단, Supabase 무료 플랜의 **파일당 50MB** 벽이 있으므로 길이와 용량을 함께 검사한다.

**④ 알림: 웹푸시 먼저** — 카카오 알림톡은 뒤로
앱 밖에서 다시 불러올 통로가 없었다. 앱화 때 FCM/APNs를 **추가**한다(교체가 아니다).

**⑤ 만 14세 미만 — 막지 않고 보호자 문자로 동의받는다**
법은 14세 미만 가입을 **금지하지 않는다.** 법정대리인 동의를 받으라고 할 뿐이다.
가족 앨범방이라 **손주가 할머니에게 음성을 보내는 것**이 핵심 장면에 가깝다.
문자는 단순 인증번호가 아니라 **무엇에 동의하는지 적은 요청문**으로 보낸다.
Firebase Phone Auth는 쓰지 않는다(유료 + 용도 불일치 + 국내 발신번호 사전등록제).

**⑥ 소셜 로그인 전면 보류**
카카오·휴대폰·구글 모두 `[준비 중]`. 애플은 제거. 최종 목표는 **카카오·휴대폰·구글**.
카카오 작업분은 보관해뒀다. **어느 소셜 제공자도 나이 확인을 대신해주지 않으므로**
(카카오 공식 답변: "단순 편의 기능일 뿐, 법적 효력을 원하면 서비스가 직접 검증하라"),
가입을 **2단계**로 나눠 추가 정보 화면에서 생년월일을 받는 방식으로 붙인다.

**⑦ GA4 계측 도입** — 포트폴리오 목적
이탈·병목·자주 쓰는 지점을 숫자로 보고 개선까지 잇는다.
**계측이 몽실이보다 먼저다** — GA4는 소급 집계가 안 되므로 개선 전 숫자를 지금 확보해야 한다.
도구는 Firebase SDK가 아니라 `@next/third-parties/google`(웹에서 Firebase Analytics = GA4).
**DB는 Supabase 그대로 간다.**

**⑧ 검증은 웹으로, 앱은 그다음**
유저 테스트는 **카톡 링크로 3초 안에 들어오는 웹**이 압도적으로 유리하다.
앱은 설치 단계에서 테스터가 증발하고, 그 설치를 **부모가** 해야 한다.
앱화 경로는 재작성이 아니라 **Capacitor 래핑**이며 그때 바뀌는 것은 푸시와 햅틱뿐이다.

**⑨ 아이폰 햅틱** — 앱으로 갈 때
웹뷰에서 `navigator.vibrate` 가 iOS Safari에서 동작하지 않는다. 지금은 시각 반응으로 대신한다.

**⑩ 강조색 분홍 → 남보라, UI는 조용히** (2026-08-25)
바탕·카드·그림자까지 전부 분홍으로 칠해 강조색이 배경에 묻혔고, 분홍 캐릭터(몽실이)와
UI가 같은 색이라 서로 밀어냈다. Airbnb 원본은 흰 바탕에 코랄을 **점으로** 쓰는데
우리는 **면으로** 칠한 것이 문제였다.

> **원칙 — UI는 조용히 있고, 색과 성격은 몽실이가 낸다.**
> Notion·Apple·Toss·당근·스테이폴리오의 DESIGN.md가 전부 같은 말을 하고 있었다.

강조색 `#5B4BE0` 은 로고의 보라 끝(`#a211c2`)에서 파랑 쪽으로 43도 당긴 값이다 —
로고와 이어지면서 몽실이의 분홍과는 부딪히지 않는다. 흰 글자 대비 5.96:1(WCAG AA 통과).
토큰만 고쳐 219곳이 따라왔다. 브랜드 마크도 직접 그린 하트 SVG에서 **실제 로고 이미지**로
바꿨다(좋아요·즐겨찾기의 하트는 기능 아이콘이라 그대로 둔다).

**⑪ 서체 Noto Sans KR → Pretendard, 굵기 900 → 700** (2026-08-25)
제목을 900으로 눌러 쓰던 화면이 **"공지·커머스"의 목소리**로 읽혔다. 다루는 감정이
쑥스러움·미안함·후회인데 소리를 지르고 있었다. 버튼만 600(토스 규율 17px/600).
dynamic-subset 92조각으로 자체 호스팅한다 — 화면에 실제로 나온 글자의 조각만 받는다.

**⑫ 사진은 선택 사항** (2026-08-25, 사용자 결정)
전에는 사진 1장 이상 + 음성 3초 이상을 **모두** 채워야 올릴 수 있었다.
목소리가 중심인 앱에서 사진을 강제하면 "지금 찍을 사진이 없어서" 마음을 못 남긴다.
DB에 사진 필수 제약이 없고 화면도 이미 0장을 처리하고 있어 서버 검사만 걷어냈다.

**⑬ 디자인 관문 — UI 작업의 필수 절차** (2026-08-26)
화면·컴포넌트 작업은 **기준 확인 → 방향 → 시안 비교 → 구현 → 마감 → 스크린샷 검증**
순서를 건너뛰지 않는다. 시안 HTML을 손으로 짜지 않고 `superdesign` 캔버스에 올려
눈으로 비교해 고른다. 규칙 전문은 `frontend/CLAUDE.md`.
→ 건너뛰었다가 같은 화면을 세 번 고쳐 세 번 다 반려된 일이 있었다(§8 참조).

**⏸ 보류 목록** — 테마·저장 용량·구독 모델, 카카오 알림톡, 감정 태그(폐기),
댓글을 사서함에 넣는 것(안 함), 답장 미션 강도 조정, 첫 24시간 온보딩.
