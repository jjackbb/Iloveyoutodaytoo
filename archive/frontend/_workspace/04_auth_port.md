## 1. 이메일 → 아이디

### 무엇을 바꿨나

화면에서 묻는 것은 **아이디 + 비밀번호**뿐이다. 이메일 입력칸은 가입·로그인 양쪽에서 사라졌다.
Supabase Auth는 이메일로만 로그인하므로, 앱이 아이디를 **내부 전용 이메일**로 바꿔서 넘긴다.

```
아이디 hongildong  →  hongildong@id.oneuldo.local  →  supabase.auth.signUp / signInWithPassword
```

사용자는 이 주소를 한 번도 보지 않는다. DB의 `users.email` 에도 넣지 않는다(아래 참조).

### 판단 기록

| 갈림길 | 정한 것 | 근거 |
|---|---|---|
| 합성 이메일 도메인 | **`id.oneuldo.local`** | `.local` 은 RFC 6762가 예약해 인터넷에 존재할 수 없는 이름이다. 누군가 그 도메인을 사서 계정 메일을 가로채는 일이 원천적으로 불가능하다. 가입 확인 메일은 Supabase에서 꺼져 있어(기존 계정 `email_confirmed_at` 이 즉시 채워짐) 실제로 메일이 나가지도 않는다. |
| 한글 아이디 | **불가 (영문 소문자 + 숫자 4~16자)** | 아이디가 그대로 이메일 주소의 앞부분(local-part)이 된다. 앞부분은 ASCII만 쓸 수 있어(SMTPUTF8을 Supabase Auth가 쓰지 않는다) 한글을 넣으면 가입이 주소 형식 오류로 거절된다. 화면에서 막지 않으면 사용자는 이유를 알 수 없는 오류만 본다. 대문자를 뺀 것도 같은 맥락 — 이메일 앞부분은 서버에 따라 대소문자를 구분해 `Hong` 과 `hong` 이 다른 계정이 되는 사고가 난다. 그래서 입력 즉시 소문자로 맞춘다(글자를 지우지는 않고 어긋나면 문구로 알린다). |
| 기존 이메일 계정(dev 계정 2개) | **그대로 이메일 로그인 유지. 아이디는 지어 넣지 않는다.** | `users.username` 은 null 을 허용하고 unique 인덱스는 null 을 여러 개 받아준다. 로그인 서버 액션의 `resolveLoginEmail` 이 입력값에 `@` 가 있으면 이메일로 보고 그대로 넘긴다. 없는 아이디를 우리가 만들어 채우면 그분들이 모르는 아이디가 생기고, 그 아이디로는 로그인이 안 된다(비밀번호는 그대로인데 주소가 달라진다). **확인함**: `aasd1228@gmail.com` 로 로그인 시도 시 형식 오류가 아니라 인증 결과("아이디 또는 비밀번호가 맞지 않아요")가 나온다 = Supabase까지 도달. |
| 마이 > 내 정보의 아이디 표시 | **마스킹하지 않고 그대로 보여준다** | 캡처 49는 그 자리에 마스킹한 이메일이 있다. 하지만 우리 식별자는 이메일이 아니라 아이디이고, 아이디는 **본인이 기억해야 로그인할 수 있는 값**이다. 내 화면에서 내 아이디를 못 읽게 하면 잊었을 때 확인할 곳이 사라진다(시니어 사용자에게 특히). 가려야 할 것은 남에게 보이는 개인정보이지 본인의 로그인 이름이 아니다. |
| 중복 아이디 | 아이디 = 계정 주소이므로 Supabase가 `user_already_exists` 로 돌려준다 → **"이미 사용 중인 아이디예요. 다른 아이디로 만들어주세요."** | 사용자에게 '이메일'이라는 말을 꺼내지 않는다. 적은 적이 없는 것이라 무슨 소린지 모른다. `users.username` 의 unique 인덱스가 한 겹 더 막는다. |

### 검증 위치

- **클라이언트**: `signup-form.tsx` — 칸을 벗어난 뒤 규칙 위반이면 Field 오류 문구
- **서버**: `lib/actions/auth.ts` — `validateUsername()` 을 다시 통과해야 signUp까지 간다
- **DB**: `users_username_format` CHECK + `users_username_key` UNIQUE

## 2. 생년월일 — 휠 선택기

### 무엇을 바꿨나

브라우저 달력(`<input type="date">`)을 걷어내고 새 부품으로 갈았다.

> ⚠️ 이 절은 **2026-08-10에 두 번 다시 짰다.** 아래가 지금 코드다. 경위는 §6에 남겼다.
> ① 처음: 년/월/일 세 칸 + 옆 [고르기] 버튼 → 사용자가 거부
> ② 두 번째: 칸 하나 + 시트 안 [직접 입력] 모드 전환 → **연도 6자리가 그대로 들어가는 회귀**
> ③ 지금: 칸 하나 + 시트 안에 숫자 칸과 휠이 **함께**. 모드 전환 없음.

- **칸은 하나다.** 값은 `1985년 8월 9일` 로 보이고, 비어 있으면 "생년월일을 골라주세요".
  누르면 아래에서 시트가 올라온다 — 참고 이미지 그대로다.
- **시트 안에는 숫자 칸과 휠이 같이 있다.** 모드를 바꾸는 버튼이 없다.
  열리면 숫자 칸에 초점이 가 있어서 **바로 칠 수 있고**, 굴리고 싶으면 아래를 굴리면 된다.
  - 치면 → 읽히는 즉시 휠 3열이 그 자리로 움직인다
  - 굴리면 → 숫자 칸 글자가 다시 쓰인다
  - 값의 주인은 **숫자 칸 글자 하나**다. 주인을 둘로 두면 어느 쪽이 맞는지 알 수 없어진다.
- **연도 4자리 제한 — `maskTypedBirthDate()` 한 곳**(`src/lib/birth-date.ts`).
  입력칸의 `onChange`를 반드시 지나므로 **타이핑·붙여넣기·자동완성이 전부 같은 길**로 들어온다.
  왼쪽부터 한 글자씩 읽어 년(4)·월(2)·일(2) 칸을 채우고, 칸이 차면 다음 칸으로 넘어간다.
  기호는 "이 칸은 여기까지"라는 뜻이라 `1985.8.9` 처럼 한 자리로 적은 달·날도 살아난다.
- `19850809` · `1985-08-09` · `1985.8.9` · `1985/08/09` · `1985년 8월 9일` 이 **전부 같은 값**으로 읽힌다.
  무엇으로 읽었는지를 칸 바로 아래 "이렇게 읽었어요 — 1985년 8월 9일" 로 보여준다.
- **연도 범위 1900년 ~ 올해** (127줄). 휠 하한과 검사 하한(`MIN_BIRTH_YEAR`)이 같은 값이다.
- 폼으로 나가는 값은 숨은 칸 하나(`birth_date`)에 `YYYY-MM-DD` 로만 실린다. 반쪽짜리 날짜는 빈 값으로 나간다.

### 판단 기록

| 갈림길 | 정한 것 | 근거 |
|---|---|---|
| 참고 이미지처럼 "입력칸을 누르면 휠" 로 할지 (**2026-08-10 사용자 확정**) | **칸 하나 + 누르면 시트. 시트 안에 숫자 칸과 휠이 함께, 모드 전환 없음.** | 바깥 칸을 "누르면 휠이 뜨는 칸"이자 "커서를 놓고 치는 칸"으로 동시에 만들 수는 없다 — 누르는 순간 시트가 초점을 가져가 바깥 칸에는 한 글자도 칠 수 없다. 그래서 **초점을 시트 안 숫자 칸으로 넘겨** 두 요구를 다 만족시켰다: 참고 이미지대로 눌러서 휠이 뜨고, 그 상태에서 그대로 칠 수도 있다. |
| 자릿수 제한을 무엇으로 걸지 | **`maxLength` 속성이 아니라 입력값 마스크(`maskTypedBirthDate`)** | `maxLength` 는 붙여넣기·자동완성을 막지 못한다. 더 중요한 건 이 칸이 년·월·일을 **한 줄에 같이** 받는 칸이라 전체 글자 수로는 연도를 제한할 수 없다는 점이다(`12345678-08-09` 도 열네 자다). 자릿수 제한은 칸 단위로만 뜻이 있고, 그래서 `onChange` 를 지나는 마스크 한 곳에 모았다. |
| 넘치는 숫자를 버릴지 다음 칸으로 넘길지 | **다음 칸으로 넘긴다** | 버리는 판을 먼저 만들었다가 브라우저에서 잡았다 — `19850809` 를 쭉 치면 `1985-08` 에서 멈추고 **일(日)을 영영 칠 수 없었다.** 년이 차면 다음 숫자는 달로 가야 한다. |
| 직접 입력 칸의 글자를 치는 도중에 고쳐줄지 | **고친다(마스크). 대신 읽어낸 결과를 바로 아래 한국어로 보여준다.** | 자동 정렬을 안 하는 판도 만들어 봤으나, 그러면 `123456` 이 칸에 그대로 남아 "연도 여섯 자리가 들어간다"는 바로 그 문제가 된다. 고치되 무엇으로 읽었는지("이렇게 읽었어요 — 1985년 8월 9일")를 손 떼기 전에 보여주는 쪽을 골랐다. |
| 생년월일 칸의 `required` | **브라우저 필수 표시를 걸지 않고 서버가 잡는다** | 이 칸은 버튼(누르면 시트가 뜬다)이라 `required` 를 걸 수 없다. 숨은 칸에 걸면 브라우저가 "보이지 않는 칸이 비었다"며 제출만 막고 아무 말도 못 해준다. 대신 서버가 비어 있을 때 "생년월일을 입력해주세요."로 되돌려주도록 `signUp` 의 검사 순서를 바꿨다(예전에는 "모든 항목을 입력해주세요"로 뭉뚱그렸다). |
| 휠 구현 방식 | 라이브러리 없이 **CSS scroll-snap + 실제 스크롤** | 스크롤을 직접 흉내 내면 관성·튕김·접근성을 전부 다시 만들어야 하고 그렇게 만든 것은 대개 진짜 스크롤보다 못하다. 줄 높이 44px = 터치 목표 최소치. |
| 휠의 접근성 | 휠은 `aria-hidden`, **같은 값을 고르는 진짜 `<select>` 3개**를 함께 둔다 | 휠은 굴려야만 쓸 수 있어 화면 낭독기·키보드에 통하지 않는다. select는 평소 `sr-only` 이고 초점이 오면 나타난다 — 키보드 사용자가 보이지 않는 곳에 갇히지 않게. 시트를 열면 초점은 숫자 칸으로 간다(그냥 두면 첫 select가 열려 휠을 가렸다). |
| 연도 범위 (**2026-08-10 사용자 지시**) | **1900년 ~ 올해, 휠·검사 같은 값** | "다 19xx 아니면 20xx 년생인데" — 예전의 "올해로부터 100년"은 1926년부터라 1900~1925년생은 굴려도 자기 해가 안 나왔다. 휠 하한을 `MIN_BIRTH_YEAR` 와 같은 1900으로 맞춰 두 곳이 어긋나지 않게 했다(`birthYearOptions()`). 값이 없을 때 휠의 첫 자리는 40년 전. |
| 만 14세 미만 보호자 동의 | **그대로 유지** | `needsGuardianConsent()` 로직·화면 모두 손대지 않았다. 새 부품이 성한 `YYYY-MM-DD` 를 줄 때만 판단이 돌아간다(예전에는 `length === 10` 만 보고 `123456-08-09` 같은 값도 판단에 들어갔다). |
| 완료 배지 색(초록) | **손대지 않음 — 회색조 유지** | 2026-08-10 사용자 확정. `globals.css` 에 초록 토큰을 새로 만들지 않는다. |
| 글자·터치 | 휠 글자 19.1px(text-lg)·선택 줄 21.25px(text-xl), 줄 높이 44px, 버튼 44/52px | 시니어 기준(기본 17px·터치 44px). 색은 전부 globals.css 토큰. 참고 이미지의 다크·초록은 가져오지 않았다. |

**생년월일 — 연도 4자리 (③판 재확인, 값은 실제 입력칸에서 읽은 것)**

한 글자씩 실제 입력 파이프라인으로 친 것과, 한 번에 밀어 넣은 것(붙여넣기)을 나눠서 봤다.

| 넣은 것 | 방법 | 칸에 남은 값 |
|---|---|---|
| `123456789012` | 타이핑 | `1234-56-78` |
| `19850809` | 타이핑 | `1985-08-09` |
| `1985.8.9` | 타이핑 | `1985-8-9` |
| `19000101` | 타이핑 | `1900-01-01` |
| `123456` | 붙여넣기 | `1234-56` |
| `123456-08-09` | 붙여넣기 | `1234-56-08` |
| `12345678-08-09` | 붙여넣기 | `1234-56-78` |
| `1985년 8월 9일` | 붙여넣기 | `1985-8-9` |

**어느 경로로도 연도 자리가 네 글자를 넘지 않는다.** 값이 이상해진 것들(`1234-56-08` 등)은
[완료]에서 막히고 "태어난 해 네 자리와 달·날을 적어주세요." 가 뜬다.
지우기(전체 선택 삭제·백스페이스)도 막히지 않고 빈 칸까지 돌아간다.

**생년월일 — 나머지**
- 시트를 열면 **숫자 칸에 초점이 있다**(모드 전환 없이 바로 타이핑됨)
- 년 휠 = **1900년 ~ 2026년, 127줄** (예전엔 1926년부터였다)
- 타이핑 `19850809` → 휠 3열이 `1985년 / 8월 / 9일` 로 따라 움직이고 "이렇게 읽었어요 — 1985년 8월 9일"
- 년 휠을 맨 위(1900년)로 굴림 → 숫자 칸이 `1900-08-09` 로 따라 바뀜
- 1월 31일 상태에서 2월로 굴림 → `1900-02-28` 로 끌려 들어오고 일 휠 줄 수도 31 → 28
- [완료] → 칸에 `1985년 8월 9일`, 숨은 값 `1985-08-09`
- 그대로 가입 → DB `birth_date: 1985-08-09`, `email: null` → 로그아웃 → 그 아이디로 로그인 성공
- 콘솔 오류·경고 없음

**합성 이메일 노출 방어 (감시자 지적분)**
DB에서 일부러 `username = null`, `email = 'authtest03@id.oneuldo.local'` 로 만들어 놓고 로그인 →
마이 화면에 **"아이디 authtest03"** 만 뜨고 `@` 는 화면 어디에도 없었다.
같은 화면에서 진짜 이메일 계정(`dev-check-02@example.com`)은 여전히 "이메일" 줄로 보인다.

Supabase 직접 확인(anon 키, 서버 액션과 같은 호출):
`signUp` 성공 → 같은 아이디 재가입 시 `user_already_exists` → `signInWithPassword` 성공 →
`users` 행이 `username: "authtest01", email: null` 로 저장됨.

**테스트 계정 정리 완료** — `authtest01`~`authtest05` 다섯 계정을 모두 `auth.users` 에서 지웠다.
남은 계정은 기존 dev 계정 2개뿐이며 이메일·프로필 모두 그대로다.

| 판 | 구조 | 연도 4자리를 막은 수단 | 결과 |
|---|---|---|---|
| ① | 년[4] 월[2] 일[2] **세 칸** + 옆 [고르기] | 년 칸의 `maxLength={4}` + `slice(0,4)` | 막혔음. **이 구조로 브라우저 확인을 했다.** 사용자가 모양을 거부 |
| ② | 칸 하나 + 시트 안 [직접 입력] 모드 전환 | 글자는 그대로 받고 **읽을 때만** 4자리 요구 | ❌ 칸에 `123456` 이 그대로 보였다. 사용자가 발견 |
| ③ | 칸 하나 + 시트에 숫자 칸·휠 **동시** | `maskTypedBirthDate()` — `onChange` 를 지나는 마스크 | 타이핑·붙여넣기 모두 막힘 (§4 표) |

**무엇을 잘못했나.** ①에서 한 "붙여넣기 123456 → 1234" 확인을, ②로 구조를 갈아엎은 뒤에도

구조를 바꾸면 그 구조에 걸려 있던 확인은 **전부 무효**로 보고 다시 돌려야 한다.

**③을 만들 때도 한 번 더 걸렸다.** 처음 쓴 마스크는 칸이 차면 넘치는 숫자를 **버렸고**,
그래서 `19850809` 를 쭉 치면 `1985-08` 에서 멈춰 일(日)을 칠 수 없었다.
이건 코드를 읽어서가 아니라 **브라우저에서 한 글자씩 실제로 쳐 보고** 잡았다.
`maxLength` 가 있다·마스크 함수가 있다는 것은 확인이 아니다.

## 7. Supabase 오류 원문 노출 막기 (2026-08-10)

**무엇이 문제였나.** `src/lib/actions/auth.ts` 의 `signUp` 마지막 줄이
`가입 중 문제가 생겼어요: ${error.message}` 로 **Supabase 원문을 화면에 그대로 붙여** 내보냈다.
중복 아이디만 한국어로 갈아 끼워져 있었고 나머지는 전부 이 길로 빠졌다.

GoTrue는 `email_address_invalid` 계열 오류에서 **문제가 된 주소를 문구 안에 담아** 돌려준다 —
`Email address "hong@id.oneuldo.local" is invalid` 같은 식이다. 그 주소는 우리가 아이디에 붙여
만든 내부 주소다(`lib/username.ts`). 사용자는 이메일을 적은 적이 없으므로, 화면에 뜨는 순간
"내가 왜 이 주소로 가입돼 있지?"부터 묻게 된다. §4에서 세워둔 원칙("합성 주소는 사람에게
절대 보이지 않는다")의 마지막 구멍이었다.

**어떻게 고쳤나.** `auth.ts` 안에 매핑 함수를 두고, 화면으로 나가는 문구는 전부 그 함수가 고른다.
원문은 `console.error` 로 **서버 로그에만** 남긴다.

| 분기 | 판별 | 화면 문구 |
|---|---|---|
| 중복 | `user_already_exists` / `email_exists` / `already registered` / `duplicate key` | 이미 사용 중인 아이디예요. 다른 아이디로 만들어주세요. |
| 요청 과다 | `over_request_rate_limit` / `over_email_send_rate_limit` / `rate limit` | 요청이 너무 많아요. 잠시 후 다시 시도해 주세요. |
| 주소 형식 거절 | `email_address_invalid` / `validation_failed` / (email+invalid) | 이 아이디로는 계정을 만들 수 없어요. 영문 소문자와 숫자로 4~16자인 다른 아이디로 만들어주세요. |
| 약한 비밀번호 | `weak_password` / `password` 포함 | 비밀번호가 너무 약해요. 8자 이상으로, 영문과 숫자를 섞어 만들어주세요. |
| 가입 차단 | `signup_disabled` / `email_provider_disabled` | 지금은 새로 가입할 수 없어요. 잠시 후 다시 시도해 주세요. |
| 그 밖 전부 | — | 가입 중 문제가 생겼어요. 잠시 후 다시 시도해 주세요. |

로그인 쪽(`signIn`)은 원래 한 줄로 고정돼 있어 새는 곳이 없었다. 두 가지만 손봤다 —
요청 과다일 때 "비밀번호가 틀렸다"고 거짓말하지 않게 분기를 하나 더 두었고,
`invalid_credentials` 가 아닌 오류는 원문을 서버 로그에 남기게 했다
(비밀번호 오타는 흔한 일이라 로그를 남기지 않는다). 계정이 있는지 없는지는 여전히 알려주지 않는다.

**브라우저 확인** (localhost:3000, 실제 Supabase, 별도 크롬 프로필)

| 시도 | 화면에 뜬 문구 | `@` · `.local` · `email` · `이메일` |
|---|---|---|
| `testdup01` 신규 가입 | (성공, 홈으로 이동) | 없음 |
| 같은 아이디로 재가입 | 이미 사용 중인 아이디예요. 다른 아이디로 만들어주세요. | 없음 |
| 맞는 아이디 + 틀린 비밀번호 | 아이디 또는 비밀번호가 맞지 않아요. 다시 확인해주세요. | 없음 |
| 없는 아이디로 로그인 | 아이디 또는 비밀번호가 맞지 않아요. 다시 확인해주세요. | 없음 |
| 한글 아이디로 로그인 | 아이디는 영문 소문자와 숫자만 쓸 수 있어요. (한글·대문자·특수문자 불가) | 없음 |

본문 전체를 긁어 네 낱말(`@`, `.local`, `email`, `이메일`)을 찾는 방식으로 봤고, 다섯 경우 모두 0건이었다.
서버 로그에는 같은 순간 `[가입] signUp 실패: "user_already_exists" "User already registered"` 가
제대로 남았다 — 원문은 로그에만 있고 화면에는 없다.

**알게 된 것.** 이 Supabase 프로젝트의 GoTrue는 `.local` 주소를 **거절하지 않는다**
(`testdup01@id.oneuldo.local` 가입이 그대로 성공했다). 그래서 주소 형식 거절 분기는
지금 당장 터지는 길이 아니라 **대비**다. GoTrue 설정이 바뀌거나 버전이 올라 주소 검사가
깐깐해지는 날, 원문 대신 저 문구가 나간다.

**테스트 계정 정리 완료** — `testdup01` 을 `auth.users` 에서 지웠고
`public.users` 도 함께 지워졌다(계단식). 계정 수는 확인 전과 같은 2개다.

**관문:** `npm run lint` · `npm run build` · `residue-scan verify.sh --skip-build` 전부 통과.

## 8. 생년월일 입력칸을 한국어 표기로 (2026-08-10)

**지시.** `참고/생년월일.png`(당근마켓)처럼 입력칸에 `1985년 8월 9일` 로 보이게 하라.
지금은 `1985-01-01` 처럼 하이픈이 보인다. **단, 키보드로 직접 치는 길은 그대로 살릴 것.**

### 고른 방식 — (a) 마스크가 만드는 구분자를 바꿨다

두 갈래가 있었다.

| | 방식 | 왜 안 골랐나 / 골랐나 |
|---|---|---|
| (a) | `maskTypedBirthDate()` 의 구분자를 하이픈 → `년`·`월`·`일` | **채택.** 치는 동안에도 늘 한국어다. 값이 들어오는 세 길(초기값·타이핑·휠)이 전부 이 한 곳을 지나므로 "어떤 때는 하이픈이 보이는" 구멍이 생길 수 없다. |
| (b) | 입력칸 `value` 를 포커스 여부로 갈아끼우기 | 편집 중에는 여전히 하이픈이 보여 참고 이미지와 다르다. 게다가 포커스 진입/이탈마다 controlled input의 값이 통째로 바뀌어 커서가 튄다. 표시 규칙이 마스크와 컴포넌트 두 곳으로 갈라지는 것도 이 부품이 세 번 갈아엎인 이유와 같은 종류의 위험이다. |

### (a)를 고를 때 풀어야 했던 것 — 지우기 함정

단위를 **자동으로** 붙이면 그 글자를 지울 수 없다. `1985년` 에서 `년` 을 지워도
마스크가 곧바로 다시 붙여 `1985년` 으로 되돌아온다. 그래서 규칙을 둘로 나눴다.

1. **마스크(`maskTypedBirthDate`)** — 뒤에 다른 칸이 있거나, 사용자가 제 손으로 기호를 찍어
   "이 칸 끝"이라고 알린 칸에만 단위를 붙인다. **지금 적고 있는 마지막 칸에는 붙이지 않는다.**
   → `19850809` 를 치는 도중에는 `1985년 08월 09` 까지만 간다. 이 함수는 **멱등**이다
   (자기 출력을 다시 넣어도 그대로다 — Node로 전 경우 확인).
2. **완성형 다듬기(`BirthDateField.handleText`)** — 년·월·일이 다 차서 `parseTypedBirthDate` 가
   값을 읽어내면 `formatBirthDateKorean()` 결과로 다시 쓴다. 0을 떼고 `일` 까지 붙은
   `1985년 8월 9일` — 참고 이미지와 같은 모양이다.
   **글자 수가 줄었으면(=지우는 중이면) 다듬지 않는다.** 이 한 줄이 지우기 함정을 막는다.

휠(`changeWheel`)과 시트를 다시 열 때(`initialText`)도 같은 `formatBirthDateKorean()` 을 쓴다.
**하이픈은 저장 형태(`YYYY-MM-DD`)로만 남고 화면에는 나오지 않는다.**

칸 아래 "이렇게 읽었어요 — …" 안내는 **칸에 보이는 글자와 다를 때만** 뜬다. 같은 말을 두 번 적지 않는다.

### 바뀐 파일
